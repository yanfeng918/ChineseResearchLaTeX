# 技术路线的"总—分"结构规范

> 评审最常见的扣分点之一：技术路线写成了与研究内容各说各话的方法罗列，看不出"哪条路线在解决哪项研究内容"。
> 本规范强制两件事：**总分结构**（先总体、后分项）与**逐项对应**（分路线与研究内容一一对齐）。

---

## 零、先确认落点

技术路线写在哪个文件，取决于项目布局（由 SKILL.md「落点解析」从 `main.tex` 解析）：

| 布局 | 示例项目 | 技术路线落点 |
|---|---|---|
| `three-part` | `NSFC_General` / `NSFC_General_Clean` / `NSFC_Young` | 并入「研究内容」文件（`2.1.研究内容.tex`） |
| `five-part` | `NSFC_Local` / `NSFC_Local_Clean` | 独立的「方案及可行性」文件（`1.3.方案及可行性.tex`），**不要塞进研究内容** |

两种布局下，以下"总—分"结构要求完全一致。五段式因为有独立文件，更应把总体路线与分路线写足，不要只留一段方法概述。

---

## 一、总体要求

技术路线必须由两层组成，缺一不可：

| 层次 | 内容 | 篇幅参考 |
|---|---|---|
| **总体技术路线（总）** | 全局主链：输入→关键环节→输出；各项研究内容在主链上的位置与依赖顺序；跑通后如何达成总目标 | 1–2 段 + 1 张技术路线图 |
| **分项技术路线（分）** | 每项研究内容对应一条，逐条展开方法与验证 | 每条 1 段或 1 组小标题 |

**硬约束**：分项技术路线的条数 **必须等于** 研究内容的项数。既不允许"有研究内容无对应路线"（缺口），也不允许"有路线无对应研究内容"（孤儿）。

---

## 二、总体技术路线怎么写

先给评审一张"从哪来、到哪去"的全局图，回答四个问题：

1. **起点**：项目的输入是什么（数据/样本/体系/已有基础）。
2. **主链**：从输入到最终产出要经过哪几个关键环节，环节之间是什么关系（串行依赖 / 并行推进 / 迭代反馈）。
3. **落位**：每项研究内容落在主链的哪一环——这一句是"总"与"分"的接缝，必须显式写出。
4. **闭合**：整条主链跑通后，如何回答立项依据提出的关键科学问题、达成总体研究目标。

写作提示：

- 总体路线是**叙述**，不是目录。不要写成"本项目技术路线包括研究内容一、研究内容二、研究内容三"这种把标题复述一遍的空段。
- 必须交代**依赖关系**：谁产出的结果是谁的输入。没有依赖关系的三条并列路线，会让评审怀疑这是三个拼在一起的小项目。
- 技术路线图建议放在研究内容开头，与总体技术路线段落相互印证；图中的模块命名要与正文研究内容名称一致，不要图上一套词、正文另一套词。

---

## 三、分项技术路线怎么写

每条分路线对应且仅对应一项研究内容，标题即写明对应关系（用自然语言，如"技术路线一：面向研究内容一的……"）。每条必须覆盖五个要素：

| 要素 | 说明 | 常见写法 |
|---|---|---|
| **输入** | 本环节从哪里拿到数据/材料/前序产物 | "以研究内容一产出的……为输入" |
| **方法与关键步骤** | 具体做什么、用什么方法、分几步 | 按步骤展开，避免只堆方法名 |
| **输出** | 产出什么可交付、可度量的结果 | "得到……模型/图谱/规范/数据集" |
| **验证口径** | 对照/基线、消融、外部验证、统计方法、泄漏防控 | 见 [validation_menu.md](validation_menu.md) |
| **衔接** | 本条产出如何进入下一环节；若为末端，说明如何汇入总目标 | "该结果将作为研究内容三的输入" |

**关键**：五要素中的"输入"和"衔接"是把分路线重新缝回总体路线的针脚。只写"方法+验证"而不写上下游接口，就会退化成方法罗列。

---

## 四、对应关系自检（内部规划用，不写入正文）

写完后建立映射表逐项核对：

| 研究内容 | 对应分路线 | 核心方法 | 验证口径 | 上游输入 | 下游去向 |
|---|---|---|---|---|---|
| 研究内容一 | 技术路线一 | | | 原始数据 | → 研究内容二 |
| 研究内容二 | 技术路线二 | | | 研究内容一产出 | → 研究内容三 |
| 研究内容三 | 技术路线三 | | | 研究内容二产出 | → 总目标 |

四项必查：

1. **数量一致**：研究内容有几项，分路线就有几条，不多不少。
2. **序号一致**：研究内容一对应技术路线一，不得错位或乱序。
3. **术语一致**：同一对象/方法/指标在研究内容与技术路线中用同一个名字，不要换着叫。
4. **依赖闭合**：每条分路线的"上游输入"都能在表中找到出处（或明确为项目外部输入），"下游去向"都能找到接收方（或明确为最终产出）。

映射表仅供内部自检，**不写入 `.tex` 正文**；正文中的对应关系用自然语言表达。

---

## 五、反模式

| 反模式 | 症状 | 改法 |
|---|---|---|
| **方法罗列** | 技术路线整段是"采用 A 方法、B 模型、C 算法"，看不出对应哪项研究内容 | 拆成分路线，每条挂到一项研究内容上 |
| **只总不分** | 只有一段总体路线，没有分项展开 | 补齐分路线，每项研究内容一条 |
| **只分不总** | 直接罗列三条平行路线，没有全局主链 | 补一段总体路线，交代依赖顺序与目标闭合 |
| **数量错配** | 研究内容三项、技术路线两条（或反之） | 按映射表补齐或合并，使数量严格一致 |
| **序号错位** | 技术路线二实际在讲研究内容三的事 | 按研究内容顺序重排 |
| **术语漂移** | 研究内容叫"多模态对齐模块"，技术路线叫"跨模态融合网络" | 统一到 [terminology_sheet.md](terminology_sheet.md) 的口径 |
| **图文不符** | 技术路线图的模块名与正文研究内容名对不上 | 以正文为准统一图中命名 |
| **孤立并列** | 三条分路线互不依赖，读起来像三个独立小课题 | 补写上下游接口，或在总体路线中说明并行的合理性 |
