# NSFC Proposal + Academic Figure Prompt Pipeline

## Purpose

This is a thin orchestration skill connecting:

1. Existing grant-writing pipeline: `nsfc-full-pipeline`
2. Grant figure planning/prompt pipeline: `nsfc-figure-pipeline`

Do not duplicate the detailed implementation of either child skill here.

Overall flow:

`Proposal writing -> fresh main.pdf -> Figure Plan -> Visual Logic -> prompts for ALL selected figures -> STOP`

## Project-level child skills

This repository stores project-specific skills directly under `<repo>/skills/`, not under `<repo>/.agents/skills/`.

Use:

- Proposal writing: `../nsfc-full-pipeline/SKILL.md`
- Figure pipeline: `../nsfc-figure-pipeline/SKILL.md`

The Azhi-ss academic figure skills remain installed globally under `/home/yanfeng/.agents/skills/` and are consumed by `nsfc-figure-pipeline`.

## Input

Required:

- Target grant project directory, `PROJECT_DIR`.

Example:

`/home/yanfeng/fund-writing/ChineseResearchLaTeX/projects/NSFC_2026_Education`

If the user provides a project directory, preserve it as the single project root for all later stages.
Do not switch projects after proposal generation.

---

## Stage A — Execute proposal writing

Read and follow:

`../nsfc-full-pipeline/SKILL.md`

Execute it completely for `PROJECT_DIR`.

The proposal-writing skill remains the authority for:

- proposal drafting
- evidence/material integration
- section generation
- revision/review
- LaTeX generation
- compilation

Expected terminal artifact:

`${PROJECT_DIR}/main.pdf`

Do not start figure planning while the proposal-writing workflow is still modifying scientific content.

---

## Gate A — Build validation

Before proceeding:

1. `${PROJECT_DIR}/main.pdf` must exist.
2. The latest proposal build must have succeeded.
3. The PDF must be readable and non-empty.
4. The PDF must be fresh relative to relevant proposal sources.
5. If any relevant source is newer, rebuild before continuing.

If the PDF is missing, failed, unreadable, or stale: STOP and fix/re-run the proposal pipeline.

Never use a previous run's PDF as a silent fallback.

---

## Stage B — Execute academic figure pipeline

Read and follow:

`../nsfc-figure-pipeline/SKILL.md`

Pass the same `PROJECT_DIR` from Stage A.

The figure pipeline MUST plan at least:

1. 研究背景图
2. 总体研究框架图
3. 技术路线图

It MUST also evaluate whether additional figures are scientifically worthwhile. Additional figures are allowed and encouraged when they provide distinct communication value and are grounded in the proposal.

Do not impose an exactly-three-figures constraint.

Expected core outputs:

```text
${PROJECT_DIR}/figures/figure-plan.md
${PROJECT_DIR}/figures/visual-logic.md
${PROJECT_DIR}/figures/prompts/*.md
${PROJECT_DIR}/figures/pipeline-summary.md
```

The exact prompt set is determined by the Figure Inventory in `figure-plan.md`.
There must be one prompt file for every selected figure.

---

## Gate B — Completion validation

The run is complete only if:

- Figure Plan exists.
- Figure Plan contains the three mandatory core figures.
- Figure Plan records all recommended additional figures, if any.
- Visual Logic exists and covers the complete selected figure set.
- Every Figure Inventory entry has a non-empty prompt file.
- `pipeline-summary.md` reports `PROMPT_ONLY_COMPLETE`.
- No image assets were generated by this orchestration skill.

If a required artifact is missing, resume from the failed figure stage rather than re-running proposal writing unnecessarily.

---

## Resume policy

Avoid destructive full reruns.

- If proposal scientific content changed: rebuild PDF, then rerun Figure Plan -> Visual Logic -> Prompts.
- If figure selection changed: rerun Figure Plan -> Visual Logic -> affected Prompts.
- If only visual style changed: keep proposal + Figure Plan, rerun Visual Logic -> Prompts.
- If only one prompt needs refinement: keep proposal + Figure Plan + Visual Logic, rerun only that prompt.
- If only later image rendering is desired: use a separate rendering workflow; do not rerun this full pipeline.

---

## Hard stop

This skill must stop after prompt generation.

Do not call or invoke any image-generation tool, renderer, MCP, API, or image-generation skill.

Final status must be `PROMPT_ONLY_COMPLETE`.
