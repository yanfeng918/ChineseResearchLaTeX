# nsfc-justification-writer 精简重构实施计划

## 通俗解释：究竟发生了什么

- **一句话说明：** 当前 Skill 为了帮助 AI 写立项依据，增加了固定文件名、固定标题命令、开篇关键词、四维度检查、阶段推断、HTML 报告和专用写入器，逐渐变成了一个绑定特定 LaTeX 模板的“小型应用程序”。
- **生活类比或具体场景：** 这类似于一个本来只需要帮人润色申请书的助手，却额外规定表格必须使用固定纸张、固定栏位和固定印章；换一种表格后，助手先报告“表格为空”，用户还要修改正文来满足检查器。
- **对应到本问题：** 固定纸张对应 `extraTex/1.1.立项依据.tex`，固定栏位对应 `\\subsubsection` 和四个内容维度，固定印章对应开篇 300 字关键词检查。真正需要 AI 判断的是论证逻辑和正文质量，而不是某一种模板的语法。
- **改变前后：** 现在是“脚本先判断模板是否符合预设，再让 AI 写作”；改进后是“AI 负责理解和改写正文，脚本只负责目标文件、diff、备份和回滚等不可逆边界”。默认先预览，用户明确确认后才写入。

## 专业判断：问题在哪里

- **当前现象：** `SKILL.md`、`config.yaml` 和 `scripts/` 同时规定了固定目标文件、固定标题解析、开篇信号词、四维度覆盖和自动写入流程；`scripts/core/` 还包含协调器、AI fallback、诊断、报告、缓存、示例推荐和版本运行目录等多层实现。
- **影响范围：** 采用自定义文件名或标题宏的项目容易被误报为空文档；理论导向与应用导向的规则可能互相拉扯；AI 为了命中检查器，可能把项目方案提前写入综述段；维护者需要同时维护提示词、配置、Python 逻辑、HTML 模板和 CLI 文档。
- **已知原因或待验证假设：** 已确认开篇检查和 `\\subsubsection` 解析存在模板耦合，内容维度回退主要依赖关键词。尚待通过现有用户调用记录确认哪些 CLI 子命令仍被外部使用，因此删除脚本前需要先做依赖盘点。

## 要达到什么目标

- **完成后的变化：**
  - Skill 以“语义写作规则 + 最小文件边界”为核心，不再把某一种 LaTeX 结构当成普遍规范。
  - 不再使用开篇 300 字、固定四维度 4/4 或固定标题命令作为默认通过条件。
  - 默认输出预览和 diff；只有用户明确要求写入时才修改文件。
  - 正文修改遵守“只改正文，不改标题、结构命令、配置和样式文件”的自然语言契约。
  - 若保留脚本，脚本只做目标确认、变更范围检查、备份和回滚，不负责语义判断。
  - 引用 key 检查和可选字数统计继续作为独立工具，不再与正文结构强绑定。

- **不在本次处理范围：**
  - 不修改用户项目中的 `.tex`、`.bib`、`.cls` 或 `.sty` 文件。
  - 不重新设计 NSFC 立项依据的学术写作规范。
  - 不自动发现并写入不确定的目标文件；路径不明确时必须询问用户。
  - 不在没有依赖盘点和回归证据的情况下直接删除所有旧 CLI。
  - 不以“AI 一定不会出错”为理由取消 diff、确认和回滚等可逆性保护。

## 改进方向

### 重写 Skill 契约：从模板驱动改为语义驱动

调整 `skills/nsfc-justification-writer/SKILL.md`，保留触发条件、科学问题/假设区分、引用守护和写作流程，删除或改写以下强制性表述：

- 默认目标文件必须是 `extraTex/1.1.立项依据.tex`；
- 必须使用四个固定小标题；
- 必须按 `\\subsubsection` 替换正文；
- 开篇必须出现“本项目/突破/切入点”信号。

新增统一的正文边界规则：

- 只改用户明确指定的正文内容；
- 保留现有标题、章节命令、环境命令、标签、引用命令和配置命令；
- 不修改 `main.tex`、配置文件、`.cls`、`.sty`，除非用户明确授权；
- 科学假设前主要写领域事实、已有研究和认知缺口，项目干预、比较、终点和技术路线在假设后集中说明；
- 无法明确区分正文范围时，先输出建议正文和 diff，不直接写入。

这一步解决的是“AI 应该怎么判断和写作”，不要求脚本理解任何特定标题命令。

### 简化配置：保留少量选项，删除模板型阈值

将 `config.yaml` 收缩为：

- Skill 元信息；
- 可选写作导向 `theoretical/mixed/engineering`，只影响提示语，不作为硬性结构判定；
- 用户显式指定的目标路径（可选）；
- 是否启用引用 key 检查、字数统计等独立工具；
- 写入保护和默认 `preview` 模式。

默认将 `output_mode` 从 `apply` 改为 `preview`。删除或降级：

- `constraints.opening` 及其 300 字信号检查；
- 固定 `min_subsubsection_count=4`；
- 将“项目切入点”作为必需维度的配置；
- 经验性页数、字数和核心文献范围的默认通过判断。

这些指标如仍有需要，应以用户显式要求或独立命令提供，不参与正文写回决策。

### 取消语法耦合的默认写入流程

将 `apply-section --title` 和 `latex_parser.py` 标记为 legacy，不再作为 Skill 的默认工作流。推荐的新流程是：

1. AI 读取用户指定文件和相关上下文；
2. AI 输出修改后的正文或 unified diff；
3. 用户确认目标文件和修改范围；
4. 仅在明确授权后应用修改；
5. 写入后再次展示 diff，并说明未修改结构命令。

如确实需要自动化写入，新增一个不解析 LaTeX 语义的轻量范围检查器，只验证：

- 目标文件是否存在且位于用户确认的项目目录内；
- 是否有其它文件被修改；
- 修改前版本是否已备份；
- 用户确认的 diff 是否与实际写入一致。

它不识别 `\\subsubsection`、`\GDNSFSubheading` 或其它宏，也不负责决定正文段落边界。

### 精简脚本：保留确定性边界，移除重复编排

先做依赖盘点，再按以下顺序处理：

- **保留或独立化：** 引用 key 检查、可选字数统计、目标范围检查、备份/回滚；
- **降级为可选：** 术语一致性、示例推荐、文献综述只读集成；
- **停止默认调用：** 开篇检查、固定四维度检查、自动阶段判定、HTML 报告、AI fallback 编排和复杂 observability；
- **最终候选清理：** `latex_parser.py`、`editor.py`、`dimension_coverage.py`、`html_report.py`、`hybrid_coordinator.py` 及只为上述流程服务的重复 prompt 封装。

清理前应搜索 `scripts/run.py`、README、项目文档和外部调用说明，先提供一版兼容提示，再删除旧接口。

### 统一 AI 提示词和参考文档

将 `writing_coach.txt`、`tier2_diagnostic.txt`、`review_suggestions.txt` 和相关参考文档统一为同一套轻量标准：

- 科学问题是要解释的未知关系、机制、性质或边界；
- 核心假设是对该未知的可证伪预测；
- 研究目标和方法不冒充科学问题；
- 项目切入点是可选表达，不是固定标题；
- 方案前置是位置风险，不是关键词禁令；
- 方法学讨论若来自外部工作，可作为综述证据保留；
- 不新增无法核验的引用、实验结果或绝对化结论。

提示词只给出判断原则和输出格式，不再复制同一套四维度、标题和阶段规则。

### 建立小型评测集后再清理旧代码

在 `skills/nsfc-justification-writer/evals/evals.json` 中加入最小评测集：

1. 标准 `\\subsubsection` 项目；
2. 自定义标题宏项目；
3. 不同文件名项目；
4. 假设前误放项目方案的文本；
5. 外部文献在假设前讨论方法、但没有变成项目动作的文本；
6. 用户要求只改正文、保留所有命令的修改任务。

每个用例至少检查：

- 不因缺少“本项目”而误报开篇失败；
- 不把自定义标题或不同文件名当成空文档；
- 能指出方案前置并给出后移建议；
- 不误报外部文献方法学描述；
- 生成 diff 中不出现未经授权的结构修改；
- 不新增缺失 bibkey 或不可核验绝对表述。

## 实施范围与顺序

1. **先冻结现状并盘点依赖。** 保存当前 Skill 快照，搜索旧 CLI、配置字段和外部文档引用，确定哪些接口需要兼容提示。
2. **先改契约和默认行为。** 更新 `SKILL.md`、`config.yaml`、README 与提示词：默认 preview，取消开篇和四维度硬门槛，加入正文边界和假设阶段规则。
3. **再切换写入方式。** 将 `apply-section` 降为 legacy，增加通用 diff/范围确认；不再把 `\\subsubsection` 作为写入前提。
4. **随后缩减脚本。** 保留引用、字数、范围、备份等独立确定性能力，停止调用或标记其余复杂编排模块。
5. **最后运行跨结构评测。** 对旧版和精简版进行同一组输入的对照，确认安全边界、引用守护和用户可读性没有回退。
6. **评测通过后再清理旧代码。** 对确认不再使用的模块做分阶段删除，并同步更新 `README.md`、`scripts/README.md`、Skill 级 `CHANGELOG.md` 和根级 `CHANGELOG.md`。

## 如何确认完成

- `SKILL.md` 不再把 `extraTex/1.1.立项依据.tex`、四个固定标题或 `\\subsubsection` 写入流程描述为普遍硬规则。
- 默认运行只输出预览和 diff，不直接写入用户文件。
- 用户明确要求修改时，AI 能保留标题、结构命令、配置命令和样式文件，并说明修改范围。
- 采用不同文件名、自定义标题宏或非 NSFC 默认结构的样例时，不再被诊断为空文档或强制改名。
- 没有“本项目”或“突破”出现在前 300 字时，不再因为开篇启发式而报警。
- 方案出现在科学假设之前时，能给出“建议后移”的解释；外部文献方法学描述不被误报为项目方案。
- 用户只要求修改正文时，diff 中没有未经授权的命令行、标题、配置文件或样式文件变化。
- 缺失 bibkey 的默认安全拒写行为仍然有效；用户明确放宽时有清晰提示。
- 至少完成标准模板、自定义宏、不同文件名、方案前置和正文保护五类回归用例。
- 旧 CLI 在移除前已有迁移说明，相关 README、架构文档和变更日志口径一致。

## 风险与待确认事项

- **AI 误改命令的风险：** 自然语言规则不能提供绝对保证，因此默认 preview、diff 和用户确认不能删除；是否保留通用范围检查器需要根据真实调用方式决定。
- **旧接口依赖：** 外部用户可能仍调用 `apply-section`、`coach` 或 `diagnose`；删除前必须完成依赖搜索并至少保留一版弃用提示。
- **目标路径歧义：** 自动猜测文件可能误写其它正文；建议优先使用用户显式路径，其次使用项目配置，再次只读追踪 `main.tex`，仍不明确时停止写入并询问。
- **功能删减过快：** 引用检查、备份和回滚仍有确定性价值，不能因“脚本过多”而一次性全部删除。
- **评测偏向单一项目：** 评测必须同时包含生物医学、工程/理论和自定义 LaTeX 结构，避免把 GDQYLH_2026 的经验再次硬编码进 Skill。

## 技术补充（按需阅读）

### 目标文件选择优先级

建议采用以下顺序：

1. 用户在本轮明确指定的文件；
2. 项目级配置中声明的文件；
3. `main.tex` 中只读追踪到的唯一正文文件；
4. 候选文件列表交给用户确认。

任何步骤都不应在目标不唯一时自动写入。

### 建议的兼容策略

- 第一阶段保留旧命令，但输出 `legacy` 提示并推荐 preview/diff 流程；
- 第二阶段停止在新文档中宣传 `apply-section` 和固定标题；
- 第三阶段删除没有调用证据的旧模块，并在 CHANGELOG 中记录迁移方式。
