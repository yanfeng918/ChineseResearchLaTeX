## 项目定位

面向复杂多步骤智能体，在上下文预算受限条件下，实现“重要信息保真压缩—冗余内容动态卸载—关键证据按需恢复—任务状态连续保持”的闭环上下文工程方法。

## 核心问题

1. 如何统一评估指令、计划、工具输出、历史决策、环境状态与外部证据的未来任务价值？
2. 如何进行分层、可控、保真压缩，避免约束丢失、证据漂移与任务状态断裂？
3. 在 Token/时延/成本预算下，如何自适应决定压缩、卸载和恢复时机？
4. 如何实现被卸载信息的可寻址、可追溯、可验证恢复？
5. 如何构建覆盖成功率、成本、时延、恢复率、一致性和鲁棒性的长程 Agent 评测体系？

## 建议研究内容

1. **任务状态感知的上下文价值建模**：建立 Context Utility Score。
2. **分层保真压缩**：原文 → 结构化事实 → 任务状态 → 高层摘要。
3. **动态卸载与按需恢复**：外部存储、可寻址索引、按需回取。
4. **闭环自适应调度**：联合优化任务成功率、Token、时延与证据保真。
5. **长程 Agent 基准与可靠性评测**：代码、科研、数据分析、多工具任务 + 公开 benchmark。

## 建议创新点

- 从“文本长度压缩”升级为“任务状态保真压缩”。
- 压缩—卸载—恢复一体化上下文调度。
- 证据可寻址与可逆追溯机制。
- 预算约束的多目标 Context Controller。
- 真实长程 Agent 系统压力测试与快手业务迁移验证。

## 与现有基础对接

- 现有 Codex/OpenClaw/科研自动化长流程可直接作为原型实验沙盒。
- 软件工程经验适合做状态持久化、索引、缓存、可恢复执行和评测平台。
- 可信评测方向可转化为压缩后事实保持、证据恢复和长程一致性的评测体系。
- 时间序列/多模态不建议强行写入主线，可作为异质上下文扩展储备。
- 本地多 GPU 与研究生团队可支持多模型、多任务、多随机种子的系统实验。

## 一年期推进建议

- M1–M2：核对附件细则；构建 benchmark 与 baseline。
- M3–M5：上下文价值建模 + 分层压缩。
- M6–M8：动态卸载 + 可寻址恢复 + ACORE Controller。
- M9–M10：可靠性/鲁棒性评测；对接快手业务验证。
- M11–M12：论文、专利/软著、源码、技术文档与结题材料。

## 申报策略

1. 不要把项目写成“科研自动化 Agent”，而要写成“通用多步骤 Agent 上下文工程”；科研自动化只是高难度验证环境。
2. 重点突出长任务 Token 膨胀、大工具结果占窗、摘要丢事实、跨阶段恢复困难、长程可靠性下降。
3. 必须把 Context Engineering 写成算法与系统问题，不是 Prompt 技巧。
4. 突出“证据不丢、可恢复、可追溯”。
5. 申报前尽快做一个小型 baseline，形成 Token–Success Pareto 曲线。
