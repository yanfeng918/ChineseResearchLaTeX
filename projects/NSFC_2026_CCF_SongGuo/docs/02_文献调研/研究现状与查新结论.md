# 动态任务下智能体持续后训练：研究现状与查新结论

## 摘要

现有证据支持低秩适配、轨迹学习、经验记忆和后处理校准各自具备研究基础，但尚不能由这些局部成果推导出动态任务下的整体可靠性。本项目将研究边界限定为文本工具智能体，在固定累计资源预算与独立测试条件下，研究任务适应、能力保持和执行风险的关系。所有性能提升均作为待检验假设，不引用其他论文的数值作为本项目预期成果。

## 引言

Agent 的关键评价对象是多步行动后的任务状态。ReAct 和 Toolformer 分别说明推理—动作交互与工具调用训练的作用；AgentBench、ToolLLM 和 τ-bench 则表明，工具系统还需要独立于语言回答的执行评估。对持续学习而言，新工具加入、旧接口变更和反馈可靠度下降是不同变化，不能合并为一个“新任务”标签。检索覆盖 2021—2026 年进展，并保留校准与持续学习的奠基论文。候选来源为公开原始论文，检索式涵盖 adaptive rank、continual instruction tuning、agent trajectory quality、action calibration、risk coverage 和 tool-agent benchmark。

## 参数效率与能力记忆

LoRA 和 QLoRA 提供低成本适配的基本路径；AdaLoRA 已直接研究参数重要性与预算分配，DoRA 研究幅度—方向分解。因此“动态调整秩”不能单独构成本项目创新。O-LoRA 已提出正交低秩子空间以降低干扰，LoRAMoE 已将多个适配器和路由结合；EWC、GEM、LAMOL 则提供参数保护、梯度约束与重放的先例。新的比较应在相同累计适配器存储、优化器状态、回放样本和GPU时约束下进行，关注任务变化时何种证据足以支持参数增配或历史适配器复用。

## 轨迹学习与验证证据

InstructGPT、Self-Instruct、LIMA 和 DPO 从不同角度研究反馈、合成样本、数据质量和偏好学习。AgentTuning 将高质量交互轨迹与通用指令混合，而 Reflexion 利用文字反馈与记忆改善后续尝试；后者不能作为已进行了参数训练的证据。Training Verifiers 与 Let's Verify Step by Step 支持分别研究结果验证和步骤验证，但数学验证器的有效性不能直接外推到工具接口。拟议轨迹质量分应区分执行正确性与训练效用：低置信正确轨迹可能是有价值的困难样本，高置信错误轨迹可能源于相关的验证器偏差。

## Agent 后训练的新进展

Agent Lightning 提供执行与训练的解耦接口，AgentFlow 研究交互过程中的规划优化。2026 年的 Agent Lightning v1.0 进一步将实际运行控制器纳入训练，指出样本拼接、优势计算和后端调度等细节影响训练稳定性。这些工作要求本项目固定运行控制器、工具版本和推理预算，避免将基础设施改进算成算法收益。其方法并未自动提供本项目所需的长期抗遗忘与跨漂移行动校准保证。最新条目目前按原始预印本身份引用。

## 可信校准与风险覆盖率

温度缩放是可解释的校准基线；Semantic Uncertainty 强调语言表达的语义等价。对工具动作，还必须定义动作是否满足前置条件、是否导致错误状态以及验证信息在行动前是否可用。Selective Classification 说明拒绝可以降低已接受样本的风险，因此必须同时报告覆盖率和全任务成功率。Conformal Risk Control 及 Adaptive Conformal Inference 的结论各有假设和统计对象，长期平均覆盖不等于任意漂移下每一步行动的安全保证。正文只将其作为方法学参照，经验风险与有限条件下的统计约束分别陈述。

## 讨论、展望与结论

四个模块均存在直接相关研究；本项目的合理切入点是证据如何在受限持续学习中分配资源、保持能力并触发校准更新。验证采用同一任务序列、相同轨迹池、固定总预算和版本化工具，通过模块消融及交互对照排除“多用了数据、参数或推理步骤”的解释。首年重点完成可重现的文本工具沙箱与公开时序补充实验；真实业务部署、多模态桌面操作和大规模全参数训练不列入核心验收。
