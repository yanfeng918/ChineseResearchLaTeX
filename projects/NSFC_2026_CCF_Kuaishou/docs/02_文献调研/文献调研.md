# 长程智能体上下文压缩、卸载与证据恢复研究进展

## 摘要

长程智能体不断接收工具结果并修改行动计划，历史轨迹的扩展会同时增加推理成本与状态管理负担。提示压缩、分层记忆和主动上下文管理分别从信息筛选、存储组织及决策控制改善这一问题。近年的方法已能根据任务反馈优化压缩，并统一学习短期与长期记忆操作。因此，研究重点需要落到更具体的机制：压缩是否保留了后续动作依赖的约束，原文回取是否仍适用于当前环境，以及恢复带来的收益是否覆盖其全部开销。静态文本问答和多轮记忆测试为分析提供了基础，具有程序化终态判定的交互环境则更适合检验长程行动可靠性。未来应通过同模型、同预算和成对环境分支的实验，分离压缩失真、检索遗漏、版本过期和任务执行错误，建立条件明确的收益边界。

## 引言

ReAct 将推理与工具行动交替组织，使模型可依据新的观察修订计划；其历史记录也随交互而增加。[ReAct](https://arxiv.org/abs/2210.03629) 为本研究提供执行骨架，不能被当作上下文管理效果的证据。Reflexion 将失败反馈写入情节记忆，说明前序经验可以影响后续尝试，但重试增加的调用数应进入成本比较。[Reflexion](https://arxiv.org/abs/2303.11366) 同样提醒我们，任务完成率不能脱离执行次数解释。工具学习研究展示了调用接口与融合工具结果的可行性，但工具使用能力、长程状态保持能力和恢复可靠性是不同研究对象。[Toolformer](https://arxiv.org/abs/2302.04761)、[ToolLLM](https://arxiv.org/abs/2307.16789) 可作为工具调用背景。

上下文窗口扩大没有消除有效利用问题。关键证据处于不同位置时，问答表现可能显著不同；这一现象由受控位置实验得到，而非由系统名义窗口推断。[Lost in the Middle](https://arxiv.org/abs/2307.03172) 支持考察信息布局；它没有证明所有新模型、所有任务都存在同样幅度的退化。LongBench 覆盖双语长文任务，RULER 在检索之外加入多跳追踪和聚合，两者适合检验压缩器的基本信息保留能力。[LongBench](https://arxiv.org/abs/2308.14508)、[RULER](https://arxiv.org/abs/2404.06654) 的静态任务分数仍不能替代多步骤动作的最终正确性。

## 从文本压缩到任务状态保持

Selective Context 用信息量筛去低价值内容，LLMLingua 通过预算控制和逐词筛选提高提示效率；LongLLMLingua 进一步处理查询相关性和位置偏差。[Selective Context](https://arxiv.org/abs/2304.12102)、[LLMLingua](https://arxiv.org/abs/2310.05736)、[LongLLMLingua](https://arxiv.org/abs/2310.06839) 提供成本较低、可直接接入的基线。这类方法表明，删除冗余内容可以减少推理负担，但内容对当前问句不显著，并不意味着它对未来步骤无用。例如，工具返回的“对象已处理”标志可能短且重复，却决定下一步是否允许再次修改该对象。

LLMLingua-2 将压缩目标蒸馏到较小模型，用词级分类保持任务无关的适用性；RECOMP 则在检索增强场景中研究抽取式或生成式压缩与选择性增强。[LLMLingua-2](https://aclanthology.org/2024.findings-acl.57/)、[RECOMP](https://arxiv.org/abs/2310.04408) 可帮助区分压缩速度、保留规则和最终任务收益。若比较方法使用不同基础模型或不同训练语料，观察到的改善就不能全部归因于压缩机制。

更接近本项目的是面向轨迹的主动压缩。ACON 根据全历史成功而压缩历史失败的案例优化自然语言压缩指南，并研究压缩器蒸馏；它已明确关注环境状态和失败信号。[ACON](https://arxiv.org/abs/2510.00615) 应列为直接竞争方法。AgentFold 使用细粒度凝练与跨步骤合并生成多尺度状态摘要，同时执行任务动作，进一步将上下文整理纳入智能体行为。[AgentFold](https://arxiv.org/abs/2510.24699) 表明“分层状态摘要”本身已不足以支撑独立创新。可以继续追问的是：对动作依赖进行显式保留后，增益来自哪些状态项、在什么任务长度与依赖跨度下出现、是否能通过删除或恢复干预被证伪。

## 分层记忆、原文回取与有效证据

MemGPT 借鉴分层存储，通过控制流把信息在上下文与外部记忆之间移动。[MemGPT](https://arxiv.org/abs/2310.08560) 已覆盖卸载与回取的基本构想。ReadAgent 生成带原文位置关联的摘要记忆，再根据问题回看原始段落；其研究包含文档阅读及网页导航扩展。[ReadAgent](https://arxiv.org/abs/2402.09727) 是“摘要加原文恢复”的直接先行工作。ACORE 因而不能将可恢复摘要写成未被研究的概念。

MemoryBank、Generative Agents、A-MEM 与 Mem0 从不同角度组织长期记忆，包括遗忘更新、反思、笔记链接及结构化抽取。[MemoryBank](https://arxiv.org/abs/2305.10250)、[Generative Agents](https://arxiv.org/abs/2304.03442)、[A-MEM](https://arxiv.org/abs/2502.12110)、[Mem0](https://arxiv.org/abs/2504.19413) 为动态记忆提供了多种实现选择。它们的任务设置与评价口径不同，不能直接排列原论文报告的分数而宣称某种结构普遍最优。

检索增强生成与稠密检索提供外部证据访问基础，Self-RAG 又使检索及反思受任务需要影响。[RAG](https://arxiv.org/abs/2005.11401)、[DPR](https://arxiv.org/abs/2004.04906)、[Self-RAG](https://arxiv.org/abs/2310.11511) 支持按需查询，而非每步灌入固定数量内容。对会修改环境的智能体，还需区分三个环节：存储中的字节可找回，候选片段与所需对象匹配，片段描述的状态在当前时刻有效。哈希只能校验前者的完整性，无法单独判断后两者。恢复失败既可能来自信息遗漏，也可能来自过期事实被正确找回。

## 统一记忆操作与预算控制

Memory-R1 通过结果反馈学习记忆增删改和选择，AgeMem 则将长期与短期记忆管理统一为策略可调用的动作。[Memory-R1](https://arxiv.org/abs/2508.19828)、[AgeMem](https://arxiv.org/abs/2601.01885) 已构成学习型记忆管理的重要先行研究。AgeMem 的长期、短期、联合训练过程也提示，统一控制并不自动消除奖励稀疏与训练开销。

对一年期项目，更可行的问题是先固定执行模型，研究小规模调度器或经校准规则的净收益。压缩、索引、回取、有效性核验及重试都使用资源；若只计算主模型输入，容易把额外调用转移成表面节省。应分别记录累计输入输出、峰值窗口、调用次数、时延分位数和成本，再在任务成功率不劣的条件下比较成本。缓存命中率与价格版本还会影响实际费用，物理Token统计和计费统计应同时保留。

2026年的新工作进一步压缩了可申报的创新空间。MemStrata直接研究检索记忆的时间有效性，PLACEMEM包含版本化记忆、来源信息和失效传播；ContextBudget明确讨论预算约束下的上下文控制，Agent Zero Memory也研究来源追溯。[MemStrata](https://arxiv.org/abs/2606.26511)、[PLACEMEM](https://arxiv.org/abs/2607.04089)、[ContextBudget](https://arxiv.org/abs/2604.01664)、[Agent Zero Memory](https://arxiv.org/abs/2608.29606) 因此应纳入直接比较，而非只与早期滑动窗口方法比较。可继续考察的是压缩后“未完成动作的证据依赖”与恢复时“版本有效性检查”的交互效应，并用真实环境动作终态检验这一组合是否超出简单模块叠加。该判断仅限本次核验文献集合，仍需通过持续查新与对照实验收窄。

更近的 Invalidation Contracts 已涉及依赖与版本失效，From Faulty Memories to Corrected Actions 涉及记忆到动作的纠错，What Does Context Compression Cost an Agent 则提示重新取证的交互开销。[Invalidation Contracts](https://arxiv.org/abs/2609.00243)、[记忆到动作纠错](https://arxiv.org/abs/2608.10502)、[压缩交互代价](https://arxiv.org/abs/2608.16370) 进一步要求将创新收窄为元数据不完备时的保留—取证配置：在相同可见信息下，有限Token应分配多少给依赖记录、多少给主动重查，且这种配置是否优于充分调优的简单组合。完整元数据仅作诊断参照；当前状态既不可见又不可查询时不能保证正确。

## 交互评测与讨论

LongMemEval 对知识更新、时间推理和拒答等能力进行检验，LoCoMo 则考察长期会话记忆。[LongMemEval](https://arxiv.org/abs/2410.10813)、[LoCoMo](https://arxiv.org/abs/2402.17753) 适合用于恢复模块诊断；它们并不充分代表可产生副作用的行动任务。AppWorld 通过数据库状态测试判断任务是否完成，WebArena 提供可控网页交互环境；这类程序化评价能减少单一语言评委偏差。[AppWorld](https://arxiv.org/abs/2407.18901)、[WebArena](https://arxiv.org/abs/2307.13854) 适合作核心与迁移环境。AgentBench 提供跨环境能力比较，SWE-bench 以代码修改测试支撑软件任务验证，GAIA 提供多工具任务；一年期项目不宜把它们全部扩展为同规模主实验。[AgentBench](https://arxiv.org/abs/2308.03688)、[SWE-bench](https://arxiv.org/abs/2310.06770)、[GAIA](https://arxiv.org/abs/2311.12983) 更适合作外部证据与选择依据。tau-bench 对规则遵从及重复运行稳定性的关注说明，一次成功和可靠完成必须分开报告。[tau-bench](https://arxiv.org/abs/2406.12045)

关键方法学难点在于反事实信息和执行噪声。未来调用哪些证据可在训练轨迹事后标注，但线上调度只能使用当时已知信息。比较压缩前后动作时，固定随机种子仍不能保证远端模型完全相同；因此需要环境快照、成对任务、多个重复，并将任务而非步骤作为统计聚类单位。合法替代行动不应因字符串不同被判成错误，应检查动作前置条件和后续任务状态。

## 展望

有价值的研究议程是建立由机制到终态的连接：先对未完成目标和动作约束进行局部干预，判断状态保留是否改变后续违例；再引入过期版本和恢复失败，区分检索率与有效证据恢复率；最后把收益放回总调用预算约束下，检验不同任务长度、噪声比例和更新频率中的适用范围。结果既可能支持某些条件下的改进，也可能揭示短任务或高频变更环境中的无收益区间。二者都能为上下文管理提供可复核的设计依据。

## 结论

压缩、分层记忆和统一调度均已有直接先行工作。面向多步骤任务的后续研究，应提供对动作依赖、证据有效性及总成本关系的可检验解释，并采用同条件交互评测证明价值。长期记忆正确性、字节恢复完整性和任务执行可靠性应分别测量，避免把局部指标替代整体结论。
