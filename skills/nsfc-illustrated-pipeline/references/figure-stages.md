# 从配图规划到最终图文稿

## 15：规划

读取文字基线 `docs/figure_source/main.text.pdf`、当前活动正文及用户的绘图规范。调用 Academic Paper Analyzer & Figure Planner，交付 `docs/Figure_Plan.md`，记录每图科学作用、原文来源、必须出现的要素、比例、预计占页、落点及优先级。

采用标书语境，不照搬论文图数和双栏宽度。背景一张、总体框架一张，每条真实路线各一张；可选图只在证据与页面空间允许时加入。写 `docs/figure_manifest.json`，格式见 [产物契约](state-and-artifacts.md)。先登记规划再开始生图，规划交付后主编排器继续 16。

## 16：配色与逐图 prompt

调用一次 Color Expert，形成全篇复用的 `docs/Figure_Palette.md`。默认 classic，颜色与结构语义绑定，兼顾灰度。随后逐图调用 Academic Figure Prompt，保存 `docs/figure_specs/Fxx.json` 和 `Fxx.prompt.md`；锁定准确中文标签、箭头方向和数学符号，英文 prompt 描述布局与画法。

每个 prompt 对应一张最终图件。JSON 不能只有文件名和标题，必须包含该技能的结构块、文字锁定、版面和呈现规范。参数、长公式和说明放 caption；不添加正文没有的模块。

## 17：串行 imagegen

完整读取当前可调用的 `$imagegen`。每图执行：

1. 用 `image-start --figure F01` 登记本次 prompt；纠错时可用 `--prompt <项目内纠错prompt.md>` 保存实际指令。
2. **单独调用一次内置 `image_gen`，仅为这个 prompt 生成一张图。** 等调用返回，才能继续。不要将多图放在一个调用里，也不要并行派发生图代理。
3. 查看输出。需要编辑本地图时，先用 `view_image` 查看，再按 imagegen 的编辑规则操作。核对中文、数据流方向、层级、裁切和科学内容。
4. 将选定 PNG 复制到清单中的项目相对路径。工具的默认输出目录由宿主管理，不假设内置工具支持目标路径参数。修订使用新的版本文件名。
5. 写本图检查证据，用 `image-record --figure F01 --call-id <实际调用标识> --evidence <项目内JSON>` 登记。调用标识取工具消息/日志，不编造。可重用同图的已验收产物，不把同次调用登记为不同图的生成。

失败用 `image-fail --reason` 关闭已确认失败的尝试，然后诊断再重试。初次加两轮纠错仍失败，保留失败项，继续其他图；`17_imagegen` 的总阶段仍不可完成。额度按当前图内容输入计数，修改科学来源/提示词后可使用新输入；额外重试用 `image-reset` 记录已修复根因。正在运行的调用不因时间长就重置。

## 18：对象级 PPT

完整读取 `image-to-editable-ppt` 及其页级/CLI 规范，输入按清单排序的 PNG，一图一页。使用 `editppt prepare → run next → dispatch/record → finalize`，不手写其状态文件。多页任务依照该技能派发真实页级子代理，主代理只管理进度、验收汇总与最终正文写入。没有所需子代理能力时如实报告依赖问题。

OCR 使用用户已有配置；用户已明确全程自动继续时，无配置可记录离线文字提示策略，结合 JSON 标签复核。其他情况遵循转换技能首次选择要求，不每页追问。

准确重建可编辑中文、框线、箭头和主要结构。保留实验照片等独立位图素材，但整页 PNG、整页 PNG 加可编辑文字覆盖都不合格。每页通过 editppt 的验证后，交付 `figures/NSFC-Figures.pptx`；写汇总证据并执行 `deck-record`。脚本仅检查基本 OOXML 结构与整页位图，不替代页级视觉检查或 editppt 真正的 `record/finalize`。

## 19：PDF

执行 `export-pdf`，脚本使用 LibreOffice 导出当前已登记的 PPT，再按清单顺序拆成各图 PDF，保留页码映射。实际查看导出结果，确认字体、中文、顺序和边界正确；将结果记入 `review/配图验收报告.md`。混合位图/矢量图如实说明，不能以 PDF 扩展名证明全图矢量化。

已经由本技能登记的 PDF 更新前保留备份；同路径出现未登记资产或用户改动时，在清单中选新文件名，不覆盖用户资产。修改现有 PPT 后重新验收、导出即可，PNG 不重复生成。此版按整本 PPT 导出，单页变更也会重新导出 PDF，但不会重建其余页或重绘 PNG。

## 20：插入

执行 `insert` 预览，核对落点后 `insert --apply`。预览和正式写入属于同一已授权操作，不需要追加用户确认。脚本以稳定标签、唯一原文锚点和受管区块实现重复执行，只改活动正文，保存被修改文件的备份。

已有非受管图占用了目标标签时，先匹配原图、保留其文字和备份，再由主代理把该图原位纳入受管区块；不能追加重复图。更改插图落点、取消已插入图时，明确处理旧区块并复核，不让孤立图悄悄留在正文。

写 `docs/figure_insertion.md`：图 ID、正文文件/段落、标签、图题、PDF 路径。实际页码在 21 构建后补齐。

## 21–22：联合验收

用 `build --phase final` 调官方 NSFC 构建。查看所有插图所在页面，检查实际中文字号、裁切、留白、图题、引用、路线与文字一致性及项目篇幅限制，写 `review/图文联合检查报告.md` 与对应证据 JSON。证据绑定本次 PDF 和构建输入的 SHA256，并列出每张图的页码。

修复时先调整图内说明、caption、局部布局与重复论述，再考虑减少可选图；不得靠无限缩图或改模板字号通过篇幅检查。正文或 BibTeX 改动回调相关引用、篇幅、去 AI 味/QC，科学方案变化才回调评审，保护事实标记。

stage 22 检查 `build_valid` 与本次检查证据。没有输入变化时复用 21 的官方构建；有变化先构建并更新相关验收。写 `review/最终图文编译检查报告.md`，区分已有/新增 warning，列出页数、缺口和交付文件。
