# 共用申请人信息

> 完整的写作工作流（开新标书三步、技能选择、技术路线规范）见 [`docs/nsfc-writing-workflow-guide.md`](../nsfc-writing-workflow-guide.md)。

本目录保存可跨基金、论文、学位材料和其他科研项目复用的申请人事实。它属于仓库级资料层，不承载任何一个具体申报项目的研究题目、技术路线、团队名单、预算方案或行政待办。

## 分层规则

```text
docs/applicants/<申请人>.md
        │
        ├── 稳定身份、教育与工作经历
        ├── 科研项目、代表作、资源与学术服务
        └── 跨项目待核验事实（F-GEN-*）
                    │
                    ▼
projects/<具体项目>/docs/00_项目事实库.md
        ├── 本项目题目、对象、数据和研究边界
        ├── 本项目团队、联系人和提交要求
        └── 本项目待核验事实（项目专属编号）
```

- 共用申请人信息是跨项目单一真相来源，不在各项目内复制完整副本。
- 项目事实库只保存当前项目特有的信息，并链接到申请人的共用文件。
- 项目正文、问卷和评审报告是派生材料；发生冲突时，先核验并更新事实库，再同步正文。
- 单项目 Release 或独立压缩包若无法访问仓库根目录，应在打包阶段生成只读快照，不应长期维护第二份手工副本。

## 状态口径

| 状态 | 含义 | 使用规则 |
|---|---|---|
| `已确认` | 申请人已确认，或有正式任务书、立项书、出版社元数据等证据 | 可按项目相关性写入正文 |
| `公开来源待终核` | 来自公开主页或既有简历，尚未逐项完成正式申报终核 | 可作草稿素材，提交前复核 |
| `待本人确认` | 现有证据不足 | 不得推断为既成事实 |
| `明确暂无` | 已确认当前不存在或尚未完成 | 可使用真实、保守的否定表述 |

用户明确回复“无”“不适用”“尚未完成”或“正式材料暂缺”时，应记录为有效事实决定。同一轮任务不再重复追问；只有它成为另一个项目的 P0/P1 必填事实时才重新核验。

## 隐私规则

- 允许记录科研申报需要且适合版本控制的职业信息，例如单位、职称、专业邮箱、公开论文和项目。
- 禁止提交身份证号、学生学号、私人手机号、家庭地址、签名扫描件、证件照片和未公开账号凭据。
- 具体项目中的参与者名单必须经本人确认；已有通讯录或学生名单不能自动视为项目成员。
- 若仓库或分支将公开发布，提交前必须再次运行敏感号码与秘密信息扫描。

## 项目接入方式

项目的 `docs/workflow_status.yaml` 可声明：

```yaml
project:
  applicant_profile_file: "../../docs/applicants/yan-feng.md"
  project_fact_file: "docs/00_项目事实库.md"
```

路径相对于项目根目录解析。项目级 `AGENTS.md` 还应明确：先读共用申请人信息，再读项目事实库；只使用与当前申请相关且状态允许的事实。
