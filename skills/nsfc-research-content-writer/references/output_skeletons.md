# 各角色输出文件的最小结构骨架（可复制粘贴）

用途：在 `output_mode=preview` 时先按“最小结构”生成草稿；在 `apply` 时按相同结构落到目标文件，确保“研究内容 → 特色与创新 → 年度研究计划”可回溯闭环。

**落点按角色引用，不写死编号**。三段式（`NSFC_General`/`NSFC_Young`）与五段式（`NSFC_Local`）的章节编号互相重叠，实际文件名以 SKILL.md「落点解析」从 `main.tex` 解析的结果为准。下文小标题用角色名，括号内给出两种布局的对应文件。

## 通用规则（先读）

约定（**仅用于 AI 内部规划与自检，禁止出现在最终 `.tex` 正文中**）：
- `Sx`：子目标编号（如 `S1`）
- `Ty`：任务编号（如 `T1`，可选）
- `Vz`：验证编号（如 `V1`，可选）

1. 若目标 `*.tex` 已包含标题命令（如 `\subsection{...}` / `\subsubsection{...}`），只替换标题命令之后的正文，不改标题与层级。
2. 特色与创新、年度研究计划对研究内容的回溯关系必须用**自然语言**表达（如”针对第一个研究目标”），不得在正文中出现 `Sx`/`Ty`/`Vz` 等编号。
3. 避免绝对化措辞；创新点用”相对坐标系”表达。

## 角色 `research_content`：研究内容

（三段式 `2.1.研究内容.tex`；五段式 `1.2.内容目标问题.tex`）

（正文建议从“问题→目标→内容→路线→验证”展开；以下为最小骨架）

```tex
% （可选）研究问题与总体目标（<=2段）

% 【规划占位，不写入正文】子目标（建议 S1–S4；每条强制：指标/对照/数据来源）
% S1：指标...；对照...；数据来源/验证...
% S2：...
% S3：...
% S4（可选）：...

% 研究内容与任务分解（正文中用自然语言对应子目标，不出现 S1/S2 等编号）
% 研究内容一：...（验证口径：对照/消融/外部验证/统计/防泄漏）
% 研究内容二：...
% ...

% ===== 技术路线（总—分两层，缺一不可）=====

% 【总】总体技术路线（1–2 段 + 技术路线图）
%   起点输入 → 关键环节 → 最终产出；
%   每项研究内容落在主链哪一环（"总"与"分"的接缝，必须显式写出）；
%   环节之间是串行依赖还是并行推进（谁的产出是谁的输入）；
%   整条链跑通后如何达成总目标、回答关键科学问题。
%   注意：不要把研究内容标题复述一遍就当作总体路线。

% 【分】分项技术路线（条数 = 研究内容项数，序号严格对应）
% 技术路线一（面向研究内容一）：
%   输入：...（原始数据/样本/已有基础）
%   方法与关键步骤：...（分步展开，不只堆方法名）
%   输出：...（可交付、可度量的结果）
%   验证口径：...（对照/基线、消融、外部验证、统计方法、泄漏防控）
%   衔接：该结果作为研究内容二的输入
% 技术路线二（面向研究内容二）：
%   输入：研究内容一产出的 ...
%   ...
%   衔接：该结果作为研究内容三的输入
% 技术路线三（面向研究内容三）：
%   ...
%   衔接：末端环节，汇入总目标 ...
```

> 「研究内容一」「技术路线一」这类中文序号是正文的正常表述，**不属于**需要净化的内部编号；需要净化的只有 `S1/T1/V1` 这类规划标记。
