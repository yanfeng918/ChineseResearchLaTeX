# 科学问题与创新点

## 核心矛盾

自然场景维语图像同时包含物体外观和场景文字。现有视觉—语言模型主要对齐“图中是什么”与资源语言描述；维语 STR 工作主要输出识别字符串；视觉枢纽工作主要服务翻译。三者都没有回答：在低资源维–汉条件下，场景文字特征能否作为稳定的第三通道，提高跨语言图像理解而不是只提高 OCR 准确率。

## 证据缺口

1. SUST/RUST 证明维语场景文字可被识别，但没有跨语言检索或理解评测\cite{kong2023sust,yang2024collaborative}。
2. Multi30k-Distant 提供维/汉/英同图描述，任务是多模态翻译而非文字增强的图像理解\cite{tayir2024visual}。
3. TextVQA 类基准几乎不含维语；不能把英文 TextVQA 增益直接写成维语结论\cite{singh2019towards,biten2019scene}。
4. 多语 CLIP 的公开测试语言很少覆盖维吾尔语\cite{chen2023altclip,chen2023mclip}。

## 科学问题与可证伪假设

### Q1 场景文字第三通道

**问题：** 在文字承载关键语义的维语场景图上，加入场景文字编码器，跨语言检索与图像理解是否显著优于无文字通道？

**假设 H1：** 在 RUST 文字可见的子集及据此构造的理解题上，融合外观与场景文字的模型，其 Recall@5 或理解准确率相对无文字通道基线提高不少于 5 个百分点；若无稳定增益，则拒绝“第三通道普遍有用”的主张，并报告仅对文字主导图像有效。

**证伪：** 消融去掉文字通道后主指标不下降，或仅 OCR 准确率上升而检索/理解不升。

### Q2 异构融合干扰

**问题：** 外观、连写维文与维/汉描述粒度不同，对比学习融合是否会相互干扰？

**假设 H2：** 采用分通道编码 + 门控或残差融合，并对外观—文本、文字—文本分别施加对齐损失，比简单拼接或单一 InfoNCE 更能同时保持物体检索和文字相关检索；若门控融合在两组任务上都不如简单拼接，则拒绝“必须复杂融合”的主张。

**证伪：** 在物体描述检索和文字相关检索上，融合模型同时低于两个单通道模型。

### Q3 视觉枢纽缓解远程语言对

**问题：** 以共享图像为枢纽，能否在缺少大规模维语 VQA 标注时，仍然得到汉↔维互检索增益？

**假设 H3：** 在 Multi30k-Distant 测试集上，图像枢纽对齐的汉查询—维描述、维查询—汉描述 Recall@5，高于仅用文本翻译再检索的流水线；若视觉枢纽不优于“OCR/描述翻译 + 单语检索”，则把视觉枢纽降为辅助模块。

**证伪：** 翻译流水线在跨语言检索上全面不低于视觉枢纽模型。

## 创新点（申请书只保留 2 条）

1. **任务创新：** 把维语场景文字从“识别正确率问题”改写为“跨语言图像理解的第三通道问题”，用检索消融而不是仅用 OCR 准确率验收。
2. **方法创新：** 在低资源维–汉数据上，联合外观编码、场景文字编码和双语描述对齐，检验视觉枢纽对远程语言对图像理解的可迁移性，而不是复现多模态翻译。

## 与既有范式的关系

- 不是新的 CLIP 架构竞赛，也不做通用民汉 NMT。
- 站在 STR + 多语图文检索 + 视觉枢纽三条线的交叉处，对象收敛到维语场景图。

## 评审可能质疑与口径

| 质疑 | 回应口径 |
|---|---|
| 5 万元做不了大模型 | 不训练基础 VLM；适配公开编码器和轻量融合头；主实验在 SUST/RUST 与 Multi30k-Distant。 |
| 没有维语 VQA 大库 | 不声称已有；拟建 200–400 题理解协议，主指标仍是检索 Recall@K。 |
| 与天池英才重复 | 天池英才对象是产业集群多模态融合；本课题对象是民族语言场景图文。 |
| 会不会做成翻译项目 | 翻译只作对照基线，验收不含 BLEU 主指标。 |
| CUTE 是机翻 | 只作文本预训练，不进金标准测试集。 |
