## 目标输出（契约）

- **写入落点：按角色解析，禁止按编号硬写**。NSFC 模板不共用一套章节编号且互相重叠——三段式的 `2.1` 是"研究内容"，五段式的 `2.1` 却是"研究基础"。必须先执行下节的落点解析，得到 `research_content` / `innovation` / `yearly_plan` /（五段式还有）`scheme` 四个角色对应的真实文件。
- **禁止改动**：`main.tex`、`extraTex/@config.tex`、任何 `.cls/.sty`
- **编排原则**：先把研究内容写成“可验证闭环”，再从中抽取创新点生成特色与创新，最后把任务拆分成三年里程碑生成年度研究计划。

## 落点解析（写作前必做）

**绝不允许用 `extraTex/2.*.tex` 这类编号 glob 选择写入目标。** 在五段式项目（如 `NSFC_Local`）上，该 glob 匹配到的是 `2.1.研究基础.tex` / `2.2.工作条件.tex` / `2.3.承担项目.tex`，会把研究内容写进研究基础且编译不报错。

解析步骤：

1. 读取 `<project_root>/main.tex`，收集所有**未被注释**的 `\input{extraTex/...}`（忽略 `%` 开头的行，忽略 `extraTex/@config.tex`）。
2. 按文件名关键词归类到写作角色：
   - `research_content`：研究内容 / 内容目标问题
   - `innovation`：特色与创新
   - `yearly_plan`：年度研究计划 / 研究计划
   - `scheme`：方案及可行性（**仅五段式有**）
3. 磁盘上存在但未被 `main.tex` 引用的文件是孤儿/禁用章节，不写入、也不算待办。
4. 把解析结果与下表对照做合理性校验；解析不出、或某角色缺失且与两种已知布局都对不上时，**停下询问用户**，不得猜测编号。

| 布局 | 示例项目 | 研究内容 | 特色与创新 | 年度计划 | 方案及可行性 |
|---|---|---|---|---|---|
| `three-part` | `NSFC_General` / `NSFC_General_Clean` / `NSFC_Young` | `2.1.研究内容` | `2.2.特色与创新` | `2.3.年度研究计划` | 无（技术路线并入研究内容） |
| `five-part` | `NSFC_Local` / `NSFC_Local_Clean` | `1.2.内容目标问题` | `1.4.特色与创新` | `1.5.研究计划` | `1.3.方案及可行性` |

**技术路线落点随布局变化**：三段式并入研究内容文件；五段式写入独立的 `方案及可行性` 文件，不要塞进研究内容。两种情况下技术路线的"总—分"结构要求完全一致。

## 写入安全约束（必须遵守）

1. 仅编辑「落点解析」得出的角色文件（三段式 3 份，五段式 4 份）；**严禁用 `extraTex/2.*.tex` 等编号 glob 批量选择写入目标**；不得修改 `main.tex`、`extraTex/@config.tex`、任何 `.cls/.sty`
2. 目标文件若已包含标题命令（如 `\\subsection{...}` / `\\subsubsection{...}`），**只替换正文内容**，不改标题与结构层级
3. 信息不全时先提问补齐，不要用“看起来像真的”的细节硬写
4. 落点解析失败或角色缺失时停下询问，不得回退到任一布局的硬编码文件名

## 工作流（按顺序执行）

1. **定位项目与目标文件**：确认 `project_root`，按上节「落点解析」从 `main.tex` 解析出各角色对应的真实文件，并只编辑这些文件；解析不出或角色缺失时停下询问，不得按编号猜测。如项目连 `main.tex` 都没有，提示用户先初始化/拷贝模板项目。
2. **固定”子目标三件套”**：把目标拆成 3–4 个子目标（内部规划时可用 `S1–S4` 编号便于自检回溯，**此编号仅用于 AI 内部规划，禁止出现在最终 LaTeX 正文中**），并对每个子目标强制写清：
   - 指标（可判定/可验收）
   - 对照/基线（与谁比、怎么比）
   - 数据来源/验证方案（样本/实验体系/评估方法）
3. **生成「研究内容」文件**（以”问题→目标→内容→路线→验证”为主线）：
   - **篇幅控制原则**（推荐值，非强制）：
     - 推荐页数：12–15 页（含图表），约占标书总页数（≤28 页）的 50%
     - 推荐字数：12000–15000 字（纯文字部分）
     - 图表策略：插入 10–20 张图通常不会显著压缩文字篇幅；图片是“提质”的重要手段
     - 核心原则：评审标准已从“字数控制”转向“页数控制”，不要以字数为导向规划篇幅
   - **组织逻辑框架（按研究类型选择）**：新版不再预设提纲，可按研究的内在逻辑自主组织：
     - 基础研究推荐框架：`科学问题提出 → 研究假说 → 验证思路 → 预期结果`
     - 应用研究推荐框架：`技术瓶颈 → 解决方案 → 实验设计 → 效果验证`
     - 通用主线（兜底）：`问题 → 目标 → 内容 → 路线 → 验证`
   - 研究问题与总体目标（不超过 2 段，用连贯段落而非条目）
   - 研究内容与任务展开（以科学叙事驱动，把验证逻辑自然编织进行文，而非逐条填写三件套）
   - 技术路线：**必须写成"总—分"两层结构，并与研究内容逐项对应**，详见下节
4. **写技术路线（"总—分"结构，强制）**：技术路线与研究内容脱节是本章最常见的扣分点——评审看不出"哪条路线在解决哪项研究内容"。因此技术路线必须分两层写，且两层都不可省略。

   **先确认落点**：三段式项目并入「研究内容」文件；五段式项目写入独立的「方案及可行性」文件（`scheme` 角色），**不要塞进研究内容**。两种情况下以下结构要求完全一致。

   **（1）总体技术路线（总）**：先给全局主链——起点输入是什么、要经过哪几个关键环节、每项研究内容落在主链的哪一环、环节之间是串行依赖还是并行推进、整条链跑通后如何达成总目标。这一段是叙述而非目录，**必须显式交代研究内容之间的依赖关系**（谁的产出是谁的输入）；只把研究内容标题复述一遍不算总体路线。技术路线图建议放在研究内容开头，图中模块命名与正文研究内容名称保持一致。

   **（2）分项技术路线（分）**：每项研究内容对应且仅对应一条分路线，标题用自然语言写明对应关系（如"面向研究内容一的……"）。每条必须覆盖五要素：**输入 → 方法与关键步骤 → 输出 → 验证口径 → 与下一环节的衔接**。其中"输入"与"衔接"是把分路线缝回总体路线的针脚，只写"方法+验证"会退化成方法罗列。

   **数量硬约束**：分路线条数必须等于研究内容项数，序号严格对应。不允许"有研究内容无对应路线"（缺口），也不允许"有路线无对应研究内容"（孤儿）。

   详细规范、映射表与反模式见 [references/technical_route_structure.md](references/technical_route_structure.md)。

5. **从「研究内容」抽取「特色与创新」**：
   - **1–3 条即可，少而精**（调研报告强调：创新点数量不在多，在于说服力）；每条从”为什么这个选择是必然的”出发，说清楚现有路线的局限、本项目的不同之处、以及这个差异预期带来什么——让评审感受到研究者真的想清楚了，而不是在填写创新点模板。
   - 避免绝对化措辞（如”首次””领先”）；如确需使用，必须给出可核验证据或改写为可审稿的相对表述。
6. **从「研究内容」推导「年度研究计划」**（三年不跨年）：
   - 每年：年度目标 → 关键任务 → 里程碑（可验收）→ 可交付成果（论文/数据/原型/规范/软件等）
   - 里程碑必须与子目标挂钩（否则评审会认为“计划与研究内容脱节”）
   - **推进逻辑**：让评审看到研究的依赖关系和递进节奏——第一年为什么先做这个、第二年为什么能做那个（避免“第一年做基础研究；第二年做深入研究；第三年做总结”的流水账）
7. **一致性校验**：
   - **技术路线 ↔ 研究内容对应检查（必做）**：在内部规划稿中建立映射表，逐项核对四件事——数量一致（研究内容几项、分路线就几条）、序号一致（研究内容一对应技术路线一，不错位）、术语一致（同一对象/方法/指标不换名字）、依赖闭合（每条分路线的上游输入都能找到出处、下游去向都能找到接收方）。发现缺口或孤儿必须补齐或合并后再落笔，不得留到用户自己发现。映射表见 [references/technical_route_structure.md](references/technical_route_structure.md)，仅供内部自检，不写入正文。
   - 检查技术路线图的模块命名是否与正文研究内容名称一致，避免图上一套词、正文另一套词。
   - 检查创新点是否能回溯到研究内容的具体任务与验证；
   - 检查年度计划里程碑是否覆盖全部子目标，且每年都有可交付物。
   - 术语口径对齐：研究对象/缩写/指标命名尽量与 `（一）立项依据`、`（三）研究基础` 保持一致（如项目中已存在）
   - **输出净化**：最终写入 `.tex` 文件前，确认正文中不含任何 `S1`/`S2`/`Sx`/`Ty`/`Vz` 等内部规划编号；如需表达对应关系，改用自然语言（如"针对第一个研究目标"）。注意"研究内容一/技术路线一"这类中文序号属于正文的正常表述，不在净化范围内。
8. **任务完成后的用户提醒**：
   - 技术路线图建议放在研究内容开头，并与总体技术路线段落相互印证。

## 写作哲学：像人类专家一样写

**两阶段工作模式**：

- **规划阶段**（内部，不写入正文）：用三件套、S1–S4 编号、验证口径菜单把研究逻辑想清楚，确保每个目标都有指标、对照和数据来源。
- **写作阶段**（输出到 `.tex`）：切换到叙事模式。把规划阶段的结论融化进连贯的段落里，让读者感受到研究者真的想清楚了，而不是在填表。

**专家写作的核心特征**：

- 有科学故事主线：读者能感受到"为什么做这个、为什么这样做、怎么证明做对了"的内在逻辑，而不是三个并列条目。
- 技术路线是这条主线的实现图：先让评审看懂全局怎么走通，再逐项交代每步怎么做。"总—分"是结构要求，但落到文字仍是叙述——分路线的五要素要融进段落，不要写成五行标签。
- 验证逻辑是叙述的一部分：不是"验证方案：对照/消融/外部验证"，而是在描述研究内容时自然说明"将通过……与……对比，以排除……的干扰"。
- 创新点有说服力：不是填写"相对 A，差异在 X，预计 Y"的公式，而是从问题出发，说清楚为什么现有路线走不通、本项目的选择是必然的。
- 年度计划体现推进逻辑：不是三年的四级结构填空，而是让评审看到研究的依赖关系和递进节奏——第一年为什么先做这个、第二年为什么能做那个。

**一个判断标准**：写完后，把正文给一位不了解这个项目的同行看，他能否在不看任何框架标注的情况下，自然地理解这个研究的逻辑？如果能，写作是成功的。
