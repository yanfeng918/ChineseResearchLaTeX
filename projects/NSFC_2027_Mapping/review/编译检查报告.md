## 三、Warning 逐条判定

### 3.1 字体告警（既有问题，非本次引入）

```text
LaTeX Font Info:    No file TUtnr.fd. on input line 35.
LaTeX Font Warning: Font shape `TU/tnr/m/n' undefined
(Font)              using `TU/lmr/m/n' instead
```

**判定：既有模板／环境问题，与本次写作无关，且对本文档无视觉影响。**

依据三点：

1. **来源**：`extraTex/@config.tex` 第 411 行 `\renewcommand{\ttdefault}{tnr}` 把等宽字体族设为 `tnr`（Times New Roman），但当前 Linux 环境未安装该字体（`fc-list | grep -ci "times new roman"` 返回 **0**），亦无 `TUtnr.fd` 字体描述文件。
2. **既有性**：同仓库 `projects/NSFC_General` 的编译日志中存在**完全相同**的告警（匹配数 1），证明这是模板在无 Times New Roman 环境下的固有表现，不是本项目正文引入的。
3. **影响范围为零**：该告警只影响 `\ttdefault`（等宽字体）。本项目正文 13 个 `.tex` 文件与 `references/reference.tex` **均未使用** `\texttt`、`verbatim`、`lstlisting` 或 `\ttfamily`，因此不存在任何实际以该字体渲染的文本。

**处理建议**：不在本流程内改动 `@config.tex`（属版式文件，超出写作流程边界）。若申请人希望消除该告警，可在安装 Times New Roman 的环境编译，或由版式维护方调整 `\ttdefault`。**不影响提交**。

### 3.2 BibTeX 告警（既有口径，属正常）

```text
Warning--Require address: radford2021clip
(There was 1 warning)
```

**判定：正常，无需处理。** `radford2021clip`（CLIP, ICML 2021）发表于 PMLR，无出版地信息，`gbt7714-nsfc` 样式对会议论文要求 `address` 字段。该条目题录经 PMLR 官方页面逐字段核验，字段缺失属客观事实，**不得为消除告警而编造出版地**。

其余 47 条均无告警——这得益于所有含 DOI 的条目均已补 `citedate` 字段（`gbt7714-nsfc` 样式的要求）。
