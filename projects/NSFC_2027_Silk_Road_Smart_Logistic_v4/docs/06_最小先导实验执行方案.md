# 最小先导实验执行方案

> 状态：已完成方案与证据包骨架，尚未采集数据、运行模型或形成结果。本文中的网络参数是预设压力档位，不是真实 2G/3G 现场测量；设备、接口、采样率、截止期和功耗口径须在首轮干运行后冻结。

## 1. 先导目标与证据边界

本先导不承担“证明完整系统有效”的任务，只回答四个可核验问题：

1. 能否形成同一受控事件的事件时间、设备采样时间和决策端到达时间三类记录，并区分未发生、未采到与未送达？
2. 能否从一次高可靠参考采集得到不可变母流，并用相同随机种子成对重放采样、压缩、缓存、续传和链路动作？
3. C1 与 C2 的候选方法能否在相同母流、动作空间、预算和数据划分下，与强匹配基线完成一次无泄漏比较？
4. 能否把每一项数字结论追溯到原始载荷、配置、日志、环境、分析单元和结果文件？

本先导允许形成的最强表述是“在基础可控场景和参数化弱网压力回放中完成了……”。在没有相应证据前，不得写成真实口岸或跨境物流现场验证、真实 2G/3G 轨迹、电子封志实测、代表性板卡验证、物理功耗或实际续航、运输—仓储货物级配对。

## 2. 最小闭环与优先级

| 层级 | 内容 | 本轮定位 | 完成后可支持的主张 |
|---|---|---|---|
| P0 | 时钟与日志干运行 | 必做 | 三时钟字段、同步残差、哈希和重放日志可用 |
| P1 | C1 受控母流与状态相关观测 | 必做 | C1 强基线、区间/拒判和敏感性分析可复算 |
| P1 | C2 成对弱网回放 | 必做 | 同母流条件下比较逐包价值与集合条件价值 |
| P2 | H3a 仓储本地漂移小实验 | 建议扩展 | H3a 可独立启动，不依赖运输—仓储配对 |
| 暂不启动 | H3b 运输事件记忆 | 门控分支 | 只有统一货物标识、配对和功效均通过后才检验 |

## 3. 受控场景

先导使用无人员识别、无真实危险货物、可重复复位的箱体或包装代理。事件定义以 [event_dictionary.yaml](../pilot/schema/event_dictionary.yaml) 为准。

| 场景 | 操作 | 参考标签 | 最低模态 | 口径限制 |
|---|---|---|---|---|
| S0 正常 | 静置或正常搬运 | 无异常 | 惯性/状态、图像 | 用于估计正常波动 |
| S1 倾斜 | 按预设角度区间完成一次倾斜并复位 | 开始、峰值、结束 | 惯性、图像 | 无角度基准时只写“受控倾斜代理” |
| S2 开启代理 | 打开箱盖或改变箱内光照并复位 | 开始、结束 | 二值状态或光照、图像 | 未部署电子封志时不得称电子封志实测 |
| S3 外观变化代理 | 使用可移除标记、折痕板或替换包装面 | 变化前后和操作时刻 | 图像 | 不损坏真实货物，不外推真实破损率 |

若当前没有任何传感设备，先用合成三时钟事件流完成 P0 的字段、弱网、缓存与重放链路；该产物只能证明软件与日志链路可运行，不能作为多模态识别性能证据。若可使用普通手机，其惯性传感器和摄像头可作为低门槛采集设备，但须在运行清单中记录型号、系统版本、应用、采样设置与时间同步误差，不能写成既有边缘硬件条件。

最低物料不绑定品牌和型号：一套可记录惯性或状态信号的采集端、一台可运行接收与弱网隔离环境的计算机、一个可复位箱体/包装代理、独立参考记录手段和足够的只读原始存储。角度基准、温湿度传感器、代表性边缘板卡和物理功率计均为条件性增强项；缺少时在清单中明确记为 not_available，不以估算值补成实测。每个运行至少设操作人和复核人；条件允许时，标签复核与模型分析由不同人员完成。

## 4. 分阶段执行

### 4.1 P0：时钟与证据链干运行

每类场景先做不少于 5 个独立运行，仅用于调试，不进入后续锁定测试。每次运行必须：

1. 生成唯一的 entity_id、session_id 和 run_id；
2. 在参考端记录事件真值时间区间和同步标记；
3. 在采集端记录 sample_time_device_ns、序号和设备时钟；
4. 在接收端记录 arrival_time_edge_ns 与完整性校验；
5. 保存采样指令、队列、丢弃、缓存、重传、续传和资源状态日志；
6. 对原始载荷、配置与日志计算 SHA-256，并登记到证据清单；
7. 记录时钟映射方法、首尾同步残差和时间单位。

P0 不设先验“漂亮精度”门槛。先根据设备时间分辨率和 5 次干运行冻结允许的同步残差，随后不得因模型结果而放宽。若事件时钟无法与设备时钟建立可审计映射，C1 只能进行软件级模拟，不得形成受控实测主张。

### 4.2 P1-C1：三时钟与状态相关观测

从高可靠本地采集得到母流 M。原始母流只读保存，所有缺失和迟到机制均在派生层生成。至少重放以下观测机制：

- O0：参考完整流；
- O1：固定周期低采样；
- O2：与当前信号幅值或资源状态相关的自适应采样；
- O3：仅改变网络到达时延和丢失，不改变本地采样；
- O4：状态相关采样与迟到共同存在；
- O5：破坏一个可观测锚点或制造支持稀疏，用于检查区间扩宽和拒判是否响应。

比较方法：

- B0：同输入、容量和训练预算的缺失掩码连续时间基线；
- B1：只保留一个时间戳的消融；
- B2：把未采到与未送达合并的消融；
- M1：三时钟、锚点、敏感性区间与拒判方法。

主指标为组平衡时间依赖 Brier 分数。辅助指标为校准误差、敏感性区间覆盖率和平均宽度、风险—覆盖曲线、拒判率、事件时间误差。每个指标必须以最上层独立运行或实体为统计单位，不能把同一事件切出的窗口当作独立样本。

### 4.3 P1-C2：同母流、共同随机数的成对重放

对每个母流运行固定网络配置、随机种子、资源初值和决策截止期，再让不同策略面对完全相同的潜在证据。动作分两层：

- 采集/编码动作：保持参考、周期采样、事件触发、保护性降采样或压缩；
- 缓存/传输动作：入队、优先级、分片、重传、断点续传和最低端侧告警。

至少比较：

- FIFO；
- 最早截止期优先 EDF；
- 逐包可加价值调度；
- 集合条件价值加置信下界，并启用相同硬安全屏障。

主指标为按独立实体和异常机会归一化的截止期加权漏警风险。辅助指标为按期完整交付率、通信字节、缓存溢出、P50/P95/P99 时延、重传量、原始证据保留率和协议硬违例数。没有物理功耗计时，能耗列只能标为 estimated 或 not_available，不得推导实际续航。

### 4.4 P2-H3a：仓储本地漂移扩展

H3a 独立于 H3b。若具备最小环境采集条件，可用温湿度加门/光照状态或固定视角图像，设计时间漂移、传感器偏移和单模态离线压力。比较规则阈值、未校准主体、后处理校准、滑动再校准和同覆盖率选择性预测，评价校准、风险—覆盖、漏/误触发与触发时延。

本扩展不需要也不得伪造运输—仓储配对。没有本地采集条件时，只保留配置与执行计划，不把公开数据或合成数据写成本地仓储预实验。

## 5. 样本、划分与统计

- 分析单位：一个独立受控运行或实体会话；窗口、帧、增强副本和网络重放副本属于同一组。
- 起步量：P0 为每类场景不少于 5 个干运行；P1 建议每类场景先积累不少于 12 个独立运行，用于检查方差、支持和流程可行性。该数值是运行下限，不是正式效能保证。
- 划分：按 entity_id 整组划分为开发、校准和锁定评估；同一母流的全部网络配置和增强副本必须跟随母体。
- 冻结：在查看锁定评估标签前冻结模型、阈值、场景、网络配置、随机种子、截止期、主次指标、缺失机制和统计脚本版本。
- 区间：按最上层独立实体自助重采样；小样本只报告点估计、区间和失败案例，不作过度显著性解释。
- 重复：每个确定性配置至少使用 3 个预注册随机种子；方法比较使用共同随机数和配对差值。
- 样本量：用 P1 的组间/组内方差估计正式实验规模，不能从锁定评估结果反推效应量或阈值。

## 6. 弱网压力配置

[weak_network_profiles.yaml](../pilot/config/weak_network_profiles.yaml) 中 W0–W4 是为了覆盖带宽受限、长时延、随机/突发丢包和间歇中断而设置的工程压力档位。Linux netem 官方接口支持 delay、loss、corrupt、duplicate、reorder、rate、slot 与 seed，适合本轮最小回放；其内核时钟粒度、TCP 队列位置等限制必须写入报告。若后续需要协议栈级仿真，可再转入 ns-3，而不是在本轮同时维护两套模拟器。

以下表述必须严格区分：

- W0–W4：参数化弱网压力回放；
- T-*：有来源、可追溯的外部或现场网络轨迹；
- F-*：现场网络实测。

当前只允许 W0–W4。任何 T-* 或 F-* 均须新增来源、许可、采集时间、采集位置、测量工具、字段定义和哈希后才能使用。

## 7. go/no-go 门

| 门 | 通过条件 | 未通过处理 |
|---|---|---|
| G0 完整性 | 每个运行有清单、配置、日志、原始载荷或明确缺失原因，必需文件哈希可复核 | 不进入模型比较 |
| G1 三时钟 | 三类时钟齐全；时钟映射、同步残差和序号单调性通过预注册阈值 | 仅做软件模拟；不声称受控三时钟实测 |
| G2 母流重放 | 同一母流与种子可重放；策略只读取当时已到达证据；迟到数据仅用于评分 | C2 不作反事实价值结论 |
| G3 支持与分组 | 每个报告层至少达到预设独立运行数；实体分组无泄漏；动作支持可诊断 | 仅报告描述统计、区间或拒判 |
| G4 安全屏障 | 无原始证据静默丢弃、分片校验冲突或非幂等续传；所有违例单列 | 任何资源节省不得抵消安全违例 |
| G5 主张映射 | 每个拟写入标书的数字都能指向结果登记和证据 ID | 不回写标书 |

## 8. 结果回写门槛

| 拟写入标书的表述 | 最低证据 |
|---|---|
| “建立了三时钟受控母流” | G0/G1/G2 通过；至少一条母流含事件、采样、到达、同步残差、质量和哈希 |
| “C1 初步优于强匹配基线” | 锁定划分、预注册指标、B0–B2、M1、组级区间、失败案例和结果登记齐全 |
| “C2 在相同弱网压力下降低截止期漏警” | 同母流共同随机数、相同预算和硬安全屏障、配对统计、协议违例为零或如实披露 |
| “支持弱网可靠上传/断点续传” | 分片、校验、缓存、重传与续传日志可复核；只写压力回放，不写现场稳定通信 |
| “低功耗/续航改善” | 有物理功率计或板级电源监测才能写实测；否则只能写估算能耗或续航代理 |
| “完成 H3a 本地先导” | 本地仓储代理数据、漂移配置、基线和选择性校准报告齐全 |

任何数字在证据包状态为 draft、unverified 或 placeholder 时都不得进入申请书正文。

## 9. 建议四周执行窗口

1. 第 1 周：设备/软件盘点、P0 干运行、时钟映射、字段和同步阈值冻结。
2. 第 2 周：完成 S0–S3 母流采集、标签复核、不可变原始层和数据说明卡。
3. 第 3 周：执行 W0–W4 成对重放，跑 C1/C2 强基线并封存锁定评估。
4. 第 4 周：完成组级统计、失败案例、证据验收和可回写句子；有余力再启动 H3a。

若可投入时间不足，优先顺序为 P0 → C1 母流 → C2 成对回放 → H3a；不以压缩报告或省略证据链换取更多模型。

## 10. 方法依据

- Linux netem 手册：支持时延、丢包、损坏、复制、乱序、速率、时隙与随机种子，并明确说明内核时钟粒度和 TCP 测试位置等局限。https://man7.org/linux/man-pages/man8/tc-netem.8.html
- ns-3 官方文档：若后续需要协议模型和离散事件网络仿真，可使用其教程、核心手册和模型库。https://www.nsnam.org/documentation/
- ACM Artifact Review and Badging：本证据包以“documented、consistent、complete、exercisable”为内部验收方向，但不声称已经通过 ACM 审核。https://www.acm.org/publications/policies/artifact-review-and-badging-current
- Datasheets for Datasets：数据说明卡记录动机、组成、采集过程、用途和限制。https://arxiv.org/abs/1803.09010
