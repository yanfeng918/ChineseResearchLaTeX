## 三、发现的问题

### P1-01｜前期基础与本项目任务之间存在可见跨度

**表现**：申请人已发表的遥感工作（RSHR+、RSSR）任务载体是视觉问答，跨模态检索工作（Feature Fusion Mamba Hashing）是通用哈希检索。**没有一项已发表工作直接落在"遥感图文检索"这一交叉点上**，而这正是本项目的任务主线。

**风险**：评审可能质疑"申请人此前未做过遥感图文检索，能否胜任"。

**当前正文的处理**：3.1 已如实说明两个方向的积累与各自边界（"不以视觉问答为研究任务""并未涉及关系证据的状态判定"）。表述诚实，但**只做了切割，没有正面论证这两条线为何能在本项目上合流**。

**建议（stage 13）**：在 3.1 增加一段，正面说明"遥感语义与空间结构理解"＋"跨模态检索表征与匹配"两条积累如何恰好构成本项目所需的能力组合，并指出 SPCA-Net（空间位置关系协同注意力）是二者的早期交汇点。不新增事实，只重组既有事实的论证方式。

### P1-02｜缺少预实验证据，且这一缺失在正文中被反复强调

**表现**：`F-GEN-07` 已确认申请人无可复用的项目级数据、代码与实验日志；数据集尚未下载核验。3.1 可行性分析、3.2 工作条件、2.1 可行性分析、4.6 其他共 **4 处**分别声明了这一状态。

**风险**：NSFC 面上评审普遍期待看到前期预研结果。事实缺失无法改变，但**同一事实在正文中出现四次**，会在阅读观感上把"没有预实验"放大为全文最醒目的信息。

**当前正文的处理**：每处声明都有其章节职责，单独看均合理。

**建议（stage 13）**：保留事实，压缩重复。建议在 3.1 保留一处完整声明，其余三处改为简短交叉引用（如"详见研究基础中的边界说明"）。**不得删除事实本身**——这是诚信要求，也是 `F-GEN-07` 的明确内容。

### P1-03｜证伪与退出路径的呈现方式可能被读作信心不足

**表现**：H1 的证伪条件与退出路径在 1.1、2.2、3.1、2.3 共 4 处出现，其中 3.1 风险一整条、2.2 特色二整段都在讲"如果假设不成立怎么办"。

**风险**：这是本稿有意为之的特色（可证伪性），学术上正确；但 NSFC 评审语境下，反复陈述"核心假设可能不成立"存在被读作"申请人自己都没把握"的风险。

**建议（stage 13）**：不删除证伪条件——它是本稿科学性的支撑。调整**语序与配比**：先讲"有什么证据支持这个假设成立"，再讲"如果不成立如何处理"。当前 2.2 特色二是先讲证伪、后讲价值，建议对调。

### P2-01｜研究内容的独立性偏弱

**表现**：三项内容围绕同一核心想法（关系证据三态）展开，内容一产出标签、内容二使用标签、内容三评测效果，呈线性依赖。

**风险**：评审可能认为"三项内容实为一项工作的三个步骤"，对 4 年期面上项目而言体量偏轻。

**缓解现状**：2.1 技术路线已设置"评测结果每年回流修订内容一与内容二"的反馈回路，一定程度上打破了线性关系。

**建议（stage 13）**：在 2.1 研究内容部分强化内容一与内容三的独立学术价值——内容一的关系证据规范与挑战集本身是可独立发布的资源贡献，内容三的分层评测协议可独立用于该领域其它方法的可比性检验。这两点在文中已有零散表述，需要提到显著位置。

### P2-02｜正文无技术路线图

**表现**：技术路线以文字描述为主，正文未插入图示。

**说明**：本流程按项目约定不代为生成或插入配图，此项仅作提示，由申请人自行决定是否补充。NSFC 面上申请书通常包含技术路线图，`figures/` 目录与 `\includegraphics` 用法已在项目 README 中说明。

### P2-03｜第（四）部分五项声明全部处于待核定状态

**表现**：4.1--4.4 与 4.6 各含一处 `F-MAP-06` 挖空。

**说明**：属**正确处理**而非缺陷。这些是申报时点的诚信声明，依赖基金委系统记录，流程不得代填。已在 [`../docs/其他说明检查报告.md`](../docs/其他说明检查报告.md) 中说明处理原则。列入此处仅为提示：**提交前必须清空**。
