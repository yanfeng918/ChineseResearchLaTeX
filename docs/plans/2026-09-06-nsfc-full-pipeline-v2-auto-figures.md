# nsfc-full-pipeline 第二版方案：写完正文后自动绘图并插入

本方案依据当前仓库技能、状态脚本及用户的 [绘图提示词.md](../../绘图提示词.md#L1) 制定。交付状态：**方案已形成，执行逻辑尚未修改**。沿用 `nsfc-full-pipeline` 技能名称；“第二版”指这次流程设计，不代表当前技能已发布为 v2.0.0。当前配置版本为 v0.4.0，现有断点 schema 为 2。

**一、目前为什么会停在文字稿**

现在的流程相当于把“写稿”和“制作配图”列成了两份独立工作单：第一份完成后，没有入口自动领取第二份。因此，一次运行可以交付文字 PDF，却不会继续生成图片、整理成可编辑 PPT、插回标书。

这有明确的本地依据：

- [SKILL.md](../../skills/nsfc-full-pipeline/SKILL.md#L20) 明确写着“不自动生成……配图”。
- [config.yaml](../../skills/nsfc-full-pipeline/config.yaml#L171) 将配图列为 `not_covered`，并说明由用户独立完成。
- [pipeline_state.py](../../skills/nsfc-full-pipeline/scripts/pipeline_state.py#L25) 只注册 00–14 阶段；[完成判定](../../skills/nsfc-full-pipeline/scripts/pipeline_state.py#L449) 没有图片、PPT、图文引用或插图后 PDF 的检查。

第二版要让用户只启动一次全流程，就得到正文、配图、可编辑 PPT 和插图后的 `main.pdf`。只生成 Figure Plan、提示词或 PNG，都不能算图文流程完成。

**二、推荐的整体流程**

保留原有 00–14 阶段 ID，在后面追加 15–22，共 23 个阶段。这样旧项目可以继续使用原有进度，文字已经完成的项目可以直接补跑绘图。

**文字写作与核查 → 文字稿编译 → 配图规划 → 统一配色与提示词 → PNG 生图 → 可编辑 PPT → 逐图 PDF → 正文插入 → 图文联合检查 → 最终 PDF 验收。**

| 阶段 | 第二版的行为 | 主要产物或通过条件 |
|---|---|---|
| 00–07 | 保留布局解析、选题、文献、方案、正文与说明写作；00 顺便检查绘图依赖 | 正文及事实缺口记录 |
| 08–13 | 保留引用、篇幅、去 AI 味、QC、评审与定点修复；篇幅规划提前考虑配图空间 | 文字稿检查与修复报告 |
| 14 | 编译文字稿，保存用于配图的稳定版本；自动进入 15 | 官方构建成功、文字稿 PDF 与来源记录 |
| 15 | 读取文字稿 PDF 及对应活动正文，调用 Academic Paper Analyzer & Figure Planner | `docs/Figure_Plan.md`，包含必选图、候选图、正文落点与页面预算 |
| 16 | 先调用 Academic Figure Color Expert，再逐图调用 Academic Figure Prompt | `docs/Figure_Palette.md`、逐图 JSON 规范与提示词 |
| 17 | 按图 ID 顺序逐个调用 `$imagegen`，每个 prompt 单独生成一张图，再逐张查看和修正 | `figures/Fxx-名称.png`，prompt、调用记录与图件一一对应，内容与文字核对通过 |
| 18 | 调用 image-to-editable-ppt，将选定 PNG 重建成一个可编辑 PPT | `figures/NSFC-Figures.pptx`，一图一页，结构及编辑性验收通过 |
| 19 | 从该 PPT 导出 PDF，并按图 ID 拆成单页图件 | `figures/Fxx-名称.pdf`，图号、页码、字体和边界检查通过 |
| 20 | 将 PDF 图件插入活动正文，补图题、标签与正文引用 | `extraTex/` 中的插图、`docs/figure_insertion.md` |
| 21 | 对插图后的稿件进行篇幅、图文一致性、可读性和相关 QC；定点修复 | `review/图文联合检查报告.md`、页面预览与复核结果 |
| 22 | 核验最终官方构建及交付清单；输入有变化才重新构建 | 最新 `main.pdf`、`review/最终图文编译检查报告.md`、就绪度 |

stage 21 为核查版面可以调用官方构建。stage 22 若确认源文件、引用图件和构建依赖指纹均未变化，可复用这次有效构建；修改过任何相关输入则必须重编译。不能用绘图前的文字 PDF 冒充最终产物。

**三、自动衔接规则：消除中途“交付即停止”**

1. 新启动的全流程默认包含绘图。stage 14 完成后，主编排器继续查询下一阶段并执行 15，不询问“是否开始绘图”。只有用户明确要求仅写文字或停在指定阶段时，才按其范围结束。
2. 绘图启动条件是文字阶段已执行到 14、PDF 有效、科学问题和研究路线足够明确。允许文字阶段存在合法 `drafted_with_gaps`；不要拿要求“硬事实全部补齐”的 `body_pipeline_ready` 当启动条件，否则又会因为批准号等无关缺口卡住配图。
3. `绘图提示词.md` 中“先不要生图，先给 Figure Plan”在本次自动模式下表示先后顺序。主流程先保存规划，再接配色和绘图，不在这里结束整个会话。
4. Figure Planner、Color Expert 和 Prompt 各自的停止条件只表示本子任务完成。主编排器接收产物、校验、写回断点，然后调用下一个子任务。
5. 全部常规步骤自动执行，包括图片检查、PPT 中文纠错、PDF 导出和正文插入。用户另有“等我确认”“只给提示词”等明确要求时，才保留对应暂停点。
6. 绘图规范按“本次用户指令 → 断点中显式指定文件 → 项目内 `绘图提示词.md` → 仓库根同名文件 → 技能内置默认规则”解析。保存来源路径和内容指纹；执行时按技能名称发现实际位置，不硬编码 `/home/yanfeng/`。

stage 00 提前检查 `$imagegen` 技能及其内置 `image_gen` 工具、外部技能、`editppt`、PPT 导出工具、中文字体和 PDF 检查能力，集中记录缺失项。能继续的文字工作照常完成；绘图依赖失效不能被静默记为绘图已跳过或已完成。

**四、按照你的绘图习惯规划图件**

对当前“三条研究路线”的要求，必须保留以下五张核心图：

| 图 ID | 图件 | 默认正文落点 |
|---|---|---|
| F01 | 研究背景与问题图 | 立项依据中研究背景、现状缺口的相邻位置 |
| F02 | 总体研究框架图 | 研究内容开头或总体方案说明之后 |
| F03 | 研究路线一技术路线图 | 第一条研究路线说明之后 |
| F04 | 研究路线二技术路线图 | 第二条研究路线说明之后 |
| F05 | 研究路线三技术路线图 | 第三条研究路线说明之后 |

实际落点由 stage 00 的正文角色映射决定。面上、青年和地区模板不能共用一套硬编码文件名。通用技能遇到其他路线数量时，依据正文采用“一条路线一张图”，不为了凑三张而创造研究内容。

延续“多多益善”的偏好，充分列出有解释价值的候选图，例如科学假说、关键机制、验证设计、年度安排和风险应对；只要证据和页面空间允许，优先纳入有独立作用的图。Figure Plan 区分必选、建议和可选，并为未纳入最终正文的候选图记录理由。五张核心图不能因程序默认图数上限而被删除。

规划时同时记录每张图的科学作用、必须出现的要素、原文来源、比例、预计插入宽度、图题草案和对应正文锚点。规划阶段的占页估计仅用于预留空间，最终以实际编译为准，不使用“一张图固定占三分之一页”等固定换算。

页数紧张时，先压缩图内冗长说明、优化图题和局部留白，再精简正文重复表达，最后调整可选图。保留中文文字的实际阅读尺寸，不靠无限缩小图片或修改模板字号满足页数。

**五、把生成质量落实到 PNG、PPT 和 PDF 三层**

全篇先确定一份配色与视觉规范。相同研究模块在不同图中使用相同颜色、术语和符号，配合线型或形状区分，兼顾灰度打印。默认使用当前 Academic Figure Prompt 支持的 classic 风格；不在子技能交接时无意切换到需要另一套提示词技能的风格。

逐图 JSON 规范锁定中文标签、模块名称、关键符号和箭头关系；英文提示词描述画法，图内标签默认保持中文。字数、字号和图宽以标书实际版面为依据，对论文技能中的双栏尺寸默认值进行场景适配。

生图阶段明确逐个调用 `$imagegen`，默认使用该技能的内置 `image_gen` 工具，执行规则如下：

- **每个 prompt 单独生成一张图。** 按 Figure Plan 的图 ID 顺序，读取对应的 `Fxx.prompt.md` 和 JSON 规范，单独发起一次内置绘图调用；不同图件使用各自的 prompt 和调用记录。
- **逐张串行执行。** 当前图生成、检查并保存结果或记录失败后，再调用下一个 prompt。不把多个独立图件的 prompt 合并成一次调用，不先生成整套拼图再裁切，也不以同一 prompt 的多个变体代替不同图件。
- **逐张查看与纠错。** 每张 PNG 都要实际查看，核对中文、方向、层级、裁切和原文一致性；失败后先诊断，再仅针对该图调用 `$imagegen` 修正。默认每图初次生成后允许两轮纠错，仍失败则记录失败原因并继续下一张独立图件，不能把失败图记为完成。
- **逐张落盘与登记。** 将内置工具返回的最终选定图像复制到项目 `figures/`，记录图 ID、实际使用的 prompt、调用记录和保存路径。已有文件默认保留，修订图使用带版本的文件名；项目引用不得只指向 `$CODEX_HOME/generated_images/` 中的默认输出。
- **不自动切换后端。** 内置模式不要求 `OPENAI_API_KEY`。内置工具不可用或失败时记录问题；只有用户明确选择 CLI/API 回退后，才按 `$imagegen` 的回退流程执行，不能仅因本机已有外部后端配置就自动切换。

可编辑 PPT 是必要交付物：文字应能编辑，框线、箭头和主要结构应按对象重建。实验照片、复杂纹理等可以是独立位图素材。禁止把整张 PNG 铺满幻灯片，或只叠一层可编辑文字，就宣称完成了对象级重建。

按 image-to-editable-ppt 的现有契约使用 `editppt` 管理准备、页任务、记录和汇总，不手改其状态 JSON。多图作为多页输入时，由该技能要求的页级子代理重建，实际并发不超过宿主可用槽位；主编排器只负责总流程和最终正文写入。若运行环境没有必需的子代理能力，明确标记该依赖阻塞，不伪装完成 PPT。

自动模式下，已配置 OCR 则使用；未配置且用户已要求全程自动继续时，记录沿用离线文字提示的选择，结合 JSON 中的准确标签核对文字。若用户没有给出该继续策略，则在首次依赖检查时遵循转换技能的选择要求，一次性说明，不到每张图再问。无需将自动模式改成要求用户逐图修改 PPT。

PDF 必须从通过检查的 PPT 导出。按固定的“图 ID ↔ 幻灯片页码”映射拆页，核对中文、页面边界和图件顺序。保留可用的文字与矢量对象；含照片等位图素材的 PDF 如实记录为混合图件，不能仅因扩展名是 `.pdf` 就宣称整图矢量化。

**六、自动插入正文，同时支持重复执行**

图件合格后，主编排器在活动正文的相关说明附近插入标准 `figure` 环境、PDF 路径、中文 `caption` 和稳定 `label`，并补一句“如图……所示”的正文引用。保留图内简短标签，把详细解释放入图题或相邻正文。

插入操作使用图 ID、章节锚点及受管注释边界定位，重复执行只更新同一插图块；不得重复生成图题、标签和引图句。优先匹配既有图的标签、内容和位置，已有 PNG 引用可以在确认属于同一图后替换为验收通过的 PDF，不批量覆盖所有图片。

只写 `main.tex` 实际引用的正文文件和项目 `figures/`，不改 `extraTex/@config.tex`、模板结构、公共字体或页眉。仅仅为了插图，不需要改写主文件的章节加载方式。路径使用项目相对路径，并检查符号链接和路径越界。

图文联合检查至少核验：

- 所有选定插入的图有真实 PDF，图题、标签和正文引用一一对应，无重复 label、悬空引用或错误编号。
- 图中的研究对象、三条路线、方法、变量、时间安排及箭头关系与当前文字一致。
- 最终 PDF 的所有插图页面都实际查看，文字可读，没有裁切、超出版心、异常大块留白或图题分离问题。
- 按项目自己的篇幅规则统计插图后页数，区分文字阶段的暂定篇幅结论。
- 根据改动重跑相关检查：图题新增引用检查来源，正文改写检查表达与事实，科学方案实质变化才重新模拟评审。无需因为调整了一张图的尺寸就重跑全部文献调研。

任何生成图都必须遵守事实库：研究假说和拟开展流程可以画成示意图；缺少真实数据时，不生成仿真的结果曲线、显著性、消融指标或“前期实验结果”。有真实数据的结果图由可追溯数据及绘图代码产生，图片模型不负责发明数值。受缺失事实影响的图显式记录相关事实 ID，其他图继续。

**七、断点与旧项目迁移**

断点仍使用 `docs/workflow_status.yaml`，计划升级为 schema 3。保留旧 00–14 阶段及历史记录，新增 15–22 和逐图记录；迁移先备份，幂等写回。不要另造一个与原断点互不相认的第二套主流程。

旧项目文字阶段完成后，迁移和对账通过即进入 15。已有 Figure Plan、PNG、PPT 或 PDF 时，先验证其来源、内容和格式，合格产物可复用；文件存在不代表对应新阶段已完成。有 PNG/PDF、缺少对象级 PPT 的项目，不能直接把 18 标记为完成。

逐图记录至少包含：图 ID、是否入选及理由、正文锚点、来源片段与事实 ID、提示词/配色指纹、PNG/PPT 页/PDF 路径及指纹、验证结果、插入标签、失败原因和重试次数。状态沿用已定义的状态词，由脚本原子维护；`editppt` 自身仍独立管理其页级工作状态，主断点只保存工作区引用和验收证据。

| 中断或变更 | 续跑范围 |
|---|---|
| 某一图生图失败 | 重试该图，保留其他已验收图 |
| PPT 某页失败 | 按 editppt 的恢复规则修复该页，再更新对应 PDF |
| 用户修改了 PPT 文字 | 验证对应页并重新导出 PDF、检查正文，无需重新生成 PNG |
| 只改图题或插入宽度 | 重跑图文检查和最终构建，不重新生图 |
| 某条研究路线发生实质变化 | 复核关联图的规划与内容；受影响图重走需要的后续步骤 |
| 图件丢失、变为零字节或被替换 | 即使旧状态为 completed，也使关联阶段失效 |
| 用户补齐某个事实 ID | 定点回填正文及使用该事实的图，并更新相关检查 |

一个容易遗漏的点是：插图本身会修改正文，而旧脚本的 08–14 都把正文作为输入。若只是扩展阶段表，会不断出现“插图使旧核查失效 → 重编译文字稿 → 绘图输入变化 → 再绘图”的循环。

第二版需明确区分**文字阶段的基线版本**和**插图后的当前版本**：stage 14 保存稳定的配图来源 PDF 及其正文来源指纹，最终 `main.pdf` 可继续更新；插图块、引图句和图题作为受管修改单独记录。纯插图修改交由 21/22 复核，不把 14 重置成重新生成配图基线；真实科学内容变化仍必须触发相关文字检查和图件复核。不能仅刷新旧报告的指纹就假装已检查新内容。

图件规划的来源跟踪应排除自身插入动作造成的无关变化，同时保留对真实原文变化的检测。构建指纹则必须包含活动正文、BibTeX、实际引用的全部 PDF 图件和其他实际构建依赖，不能继续只检查 `main.pdf` 非空。

临时生图结果、页任务、预览和日志放入 `.bensz-api/task-.../nsfc-full-pipeline/` 的任务工作区，LaTeX 中间文件使用 `.latex-cache/`。稳定交付与可恢复记录不依赖只有模型记忆知道的临时路径。

完成判定建议保留旧字段并增加图文层：

| 字段 | 含义 |
|---|---|
| `body_pipeline_ready` | 保留文字层含义：文字阶段及适用于当前文字版本的复核完成，无硬事实缺口和未写作占位 |
| `figures_ready` | 本次入选图件全部完成生成、PPT、PDF 和正文插入，逐图检查通过，图内事实缺口已清除 |
| `illustrated_body_ready` | 文字与配图均就绪，21/22 完成，最终 PDF 与当前源文件和引用图件一致 |
| `submission_ready` | 自动绘图模式下还要求 illustrated_body_ready，且摘要、申请代码、预算、声明和附件全部完成或明确不适用 |

合法事实缺口允许继续绘图和编译，但相关就绪度保持 false，交付时列出缺口。最终汇报除阶段进度外，还需列明“规划几张、入选几张、生成几张、PPT 完成几页、导出几张、插入几张”。任何入选图件失败，都不能宣布图文全流程完成。

若用户明确选择仅文字范围，应在运行记录和最终报告中说明该范围，保留旧文字交付能力；这种交付不能被表述为配图已完成。

**九、实施范围与顺序**

1. **先落实自动执行契约。** 修改 `skills/nsfc-full-pipeline/SKILL.md`、`config.yaml`，移除配图排除项，加入自动衔接、各阶段产物和结束条件；新增 `references/stages-15-22.md`，同步原有阶段及断点文档。保持主 SKILL 不超过 500 行。
2. **再扩展状态与产物验证。** 修改 `pipeline_state.py` 的迁移、阶段顺序、输入/输出声明、完成验证、对账及 readiness；添加最小图件管理辅助脚本，承担路径、PPT/PDF 结构检查、逐页映射、受管插入及指纹管理。科学语义、配图构思和视觉判断仍由 AI 完成，不再开发另一套绘图平台。
3. **接入现有技能并完成样板验证。** 在 `skills/external-dependencies.yaml` 登记 Figure Planner、Color Expert、Prompt 和 image-to-editable-ppt 的真实依赖，按当前宿主发现能力加载；通过宿主加载 `$imagegen` 并逐个调用内置绘图工具，不复制或修改系统技能源码。用隔离项目完整验证五张核心图的生成、重建、导出、插入和最终构建。
4. **同步用户入口和交付说明。** 更新技能版本与 CHANGELOG，使用 write-skill-readme 维护技能 README；同步根 README、`skills/README.md`、根 CHANGELOG 和 `NSFC基金项目写作操作步骤.md` 的相关说明，清理“配图须单独调用”等过期口径。项目自有技能只修改 `skills/`；通过 `sync_project_skills.py sync` 和 `check` 更新、核验受管入口，不直接修改用户级技能副本。

实现时需要特别说明：用户这次引用了全局技能路径。第二版应通过项目入口或明确读取仓库 `skills/nsfc-full-pipeline/SKILL.md` 使用，避免继续加载全局旧副本而再次跳过绘图。全局旧副本的归档另遵循仓库既有规则，不作为本次方案或后续正常执行的默认动作。

**十、如何确认第二版真的解决了问题**

所有测试和验证在 `tests/` 的子目录中执行，例如 `tests/nsfc-full-pipeline-v2/`；不在仓库根运行测试，不直接用用户现有标书做破坏性验证。

| 验收场景 | 必须观察到的结果 |
|---|---|
| 从头运行，正文有三条研究路线 | 自动完成五张核心图、可编辑 PPT、逐图 PDF、正文插入及最终编译 |
| 五个不同的绘图 prompt | 按顺序逐个调用 `$imagegen`，初次生成共五次独立调用、每次一张图；逐张检查落盘，纠错调用另行记录 |
| 子技能完成 Figure Plan 或提示词 | 主流程继续推进，不在中间产物处结束 |
| 已完成旧 00–14 的项目续跑 | 保留有效文字工作，从缺失的配图步骤继续 |
| 第三张图失败后恢复 | 已验收的其他图不重复生成，失败图不被计为完成 |
| 连续执行两次插入 | 无重复插图、图题、引图句和 label |
| 改一页 PPT 或换一个 PDF | 对应图件和最终构建失效，旧 main.pdf 不能通过就绪判定 |
| 只调整插图宽度 | 正确复核版面，不循环回到文字写作和整套生图 |
| 正文有批准号待补 | 背景、框架和已确定路线照常出图，提交状态仍为未就绪 |
| 没有前期实验数据 | 不生成虚假的结果图，准确记录证据缺口 |
| 插图后超页、错字或裁切 | 联合检查发现并定点修复，不能只凭编译退出码宣告通过 |
| 面上/青年与地区模板 | 分别插入实际活动正文，孤儿文件和模板样式保持不受影响 |
| PPT 只有整页 PNG | 编辑性验收失败，不能进入“配图完成”状态 |

状态、迁移、重复插入和失效逻辑用确定性测试覆盖；内容、PPT 编辑效果和最终 PDF 版面通过一次真实完整试跑验收。构建使用现有官方 `nsfc_project_tool.py`，报告零错误以及已有/新增 warning。尚未执行的检查不得在报告中写成通过。

本次方案阶段已只读确认：本机能找到 `editppt`、LibreOffice、XeLaTeX、PDF 检查工具及 PyMuPDF，所需四个外部技能文件可读取。该检查仅证明入口存在，尚未验证绘图调用、转换运行时和中文字体的端到端可用性；实际实施时在隔离验证目录完成。
