## 四、编译与校验

```bash
xelatex -interaction=nonstopmode -halt-on-error -output-directory=.latex-cache main.tex
xelatex -interaction=nonstopmode -halt-on-error -output-directory=.latex-cache main.tex
cp .latex-cache/main.pdf ./main.pdf
```

两次编译即可（无参考文献，不需要 bibtex）。产出必须是 **14 页 A4**。

### 溢出校验（必做）

固定框模板中文字溢出**不会产生 LaTeX 警告**，必须单独检查。改动 `content.tex` 后运行：

```bash
pdftotext -bbox-layout main.pdf /tmp/bbox.html
```

再比对每个 `\ApplicationAnswer{y}{高度}{\宏名}` 的框底坐标与该框内文字的最大 `yMax`。
判定规则：只统计 `yMin` 落在框内的行，否则会误把下一栏标题算成溢出。

目视抽查同样必要：`pdftoppm -f <页> -l <页> -r 100 -png main.pdf /tmp/chk`

## 五、写作原则

### 企业牵头的重心

申报单位是企业而非高校，强弱项与高校标书相反：

| 栏目 | 应写 | 不应写 |
|---|---|---|
| 前期任务与成果 | 口岸运营资历、真实业务数据、既有信息化系统、试点资质 | 论文专利清单 |
| 科研条件支撑 | **最强项**：边境仓实景、真实线路、可实测弱网现场、部署空间 | 实验室仪器堆砌 |
| 负责人及骨干 | 企业实施能力，并明示核心技术研发由协作高校承担 | 虚构企业方论文专利 |

卖点顺序：真实场景 → 真实数据 → 可落地示范 → 营收带动 → 技术指标 → 学术产出。

### 必须保持的中性表述

1. 部署地点、设备数量、测试周期未确认前，写"在项目确定的业务场景开展现场验证"
2. 样本规模、弱网参数、计时起止点由任务书或测试大纲冻结，不在申报书中推测
3. 第三方检测用条件式："如指南、任务书或项目组确认需要，则委托具备资质的第三方机构检测"
4. **不虚构**专利、软件、论文名称及作者、发明人、权属份额
5. 除四项硬指标外不新增数值承诺
6. 项目级预期性指标（服务企业 100 家、人才 30 人、培训 500 人次、新增营收 5000 万元）
   依赖项目整体示范，须注明属项目级，不写成课题二单独承诺
7. 材料不足的栏目宁可留空，不编造——专项评审对企业实力栏的编造敏感
